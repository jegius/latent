# Functional style of `selfhost/src/*.lat`

This document is a style agreement for the **sources of the self-hosted
compiler** in the Latent subset (`selfhost/src/*.lat`, generated by
`selfhost/shc.lat`). It does not require rewriting the compiler in a functional
language: `shc.lat` remains a procedural compiler with its state in linear
memory. The goal is **functionally clean boundaries**: predictable queries,
explicit effects, and no hidden global mutations.

The rules apply to new and modified code. Legacy code is brought into line with
them as it is decomposed, not in a single "big bang".

## 1. The model: queries, effects, and state

The Latent subset has no structs, value arrays, or closures in the role of the
compiler's standard data structure. All state is **linear memory** laid out in
`00_abi.lat`. So "functional" here means not the absence of memory but
**access discipline** toward it.

Three categories of functions:

| Category | What it does | Name | Examples |
|---|---|---|---|
| **Query** | Reads arguments and memory only, writes nothing | `get_*`, `find_*`, `is_*`, `*_len`, `nf`, `tok_kind`, `tok_val` | `find_local`, `find_str`, `name_eq`, `local_tp` |
| **Effect** | Writes to an explicitly named sink: a buffer, a table, a state slot | `emit_*`, `ev_*`, `b*`, `add_*`, `set_*`, `scan_*`, `store*` | `ev`, `bput`, `add_local`, `set`, `scan_classes` |
| **Mixed** | Query + effect | **forbidden**; split into `find_*` + `add_*` | — |

Rule: **if a function writes, it is visible from its name and its signature**.
The reader must not have to guess that `get_x()` actually creates a record or
that `check_y()` moves the cursor.

### 1.1. Where state is allowed

The single source of truth about memory is `00_abi.lat` (the address map and the
`get`/`set` accessors). Everywhere else:

* **no numeric addresses** (`load32(2260992 + ...)`), only the named map
  functions (`ST()`, `TSTK()`, `ERRB()` …);
* **no new global slots** without an entry in the `00_abi.lat` map: address,
  size, stride, owner, lifetime;
* a state slot is **explicitly passed state**, not a hidden variable:
  `get(0, PC)` reads as "the PC field of the compiler state".

### 1.2. Slot ownership and pass direction

Every slot has exactly one owner per compilation phase:

| Phase | Who writes | Who reads |
|---|---|---|
| `tokenize` | `KIND`, `TVAL`, `TLEN`, `NT` | `scan_*`, `tc_*`, `compile_*` |
| `scan_*` (classes/enums/signatures/lambdas) | `CLN*`, `FLD*`, `METH*`, `VARN*`, `LAM*`, `CAP*`, `FNOFF/FNLEN/FNNP`, `FNRET` | `tc_*`, `compile_*` |
| `tc_*` (type checking) | `TV_*`, `FRETTY`, `ERRB`, `status` | `compile_*` (`status` only) |
| `compile_*` (codegen) | `FNB`, `CODEB`, `BODYC`, `CODEOF/CODELEN`, `DATAB`, `status` | `build_module` |
| `build_module` | `OUTB` | the host (ABI) |

A pass must not pick up data that is not filled in yet, and must not write into
the previous phase's tables. Violating this rule is the main source of flaky
bugs and stage1/stage2 divergences.

## 2. Pure functions

A function is **pure with respect to the compiler** if its result depends only
on its arguments and on the documented slots it reads, and it does not modify
memory. Requirements:

1. **No hidden flags.** Do not introduce `let failed = 1;` "for the whole
   compiler". An error is the documented `status`/`ERRB` channel
   (`45a_tc_core.lat`), not a side global variable.
2. **Predicates do not mutate.** `is_ident_kind`, `is_for_in`, `is_field_start`,
   `is_index_assign` must be safe for repeated calls.
3. **Lookup separate from insertion.** `find_*` returns an index or `-1` and adds
   nothing. `add_*` adds and returns an index. Do not merge them into
   `find_or_add_*`, or a hidden effect appears.
4. **Idempotent queries.** Two `tok_kind()` calls in a row without `next_token`
   give the same result; two `find_local` calls give the same index.
5. **Explicit arguments.** Pass `offset`, `len`, `slot`, `class` explicitly. Do
   not read a "global current function" if it can be passed as a parameter;
   `CURFI()` is the exception for recursive codegen helpers.

Examples from the code:

```text
// A pure query: writes nothing, returns -1 when not found.
fn find_local(off, ln) -> int { ... }

// An explicit effect: adds a record and returns the slot.
fn add_local(off, ln, idx) -> int { ... }

// A pure query against the state.
fn nf() -> int { return get(0, 2); }

// An explicit emission effect: writes a byte into the body of the current function.
fn ev(b) -> int { return bput(FNB(), b); }
```

## 3. Side effects

An effect is acceptable if:

* it writes **only to the documented sink** (a buffer, a table, a slot);
* it is named so that the effect is visible (`emit_`, `ev_`, `bput`, `add_`,
  `set_`, `scan_`, `store`);
* it does not touch other sinks "along the way";
* it does not reorder byte emission without a fixed-point test.

Allowed codegen sinks:

| Sink | Purpose |
|---|---|
| `FNB` | the body of the current function (instruction emission) |
| `BODYC` | the final function body / the helper body |
| `CODEB` | all function bodies |
| `SCRB` | the scratch buffer for WASM sections |
| `OUTB` | the finished module |
| `DATAB` | the data section of string literals |
| `00_abi` tables | registration of classes/enums/lambdas/types |
| `status`, `ERRB` | compilation errors |

Rules:

* **Emission is an effect, not a query.** `emit_*` may return `0` or a length,
  but it must not be used in arithmetic as a "pure" value.
* **Byte order is semantic.** Emission must not be "optimized" by changing the
  order of instructions without differential tests and a `stage2 === stage3`
  check.
* **No hidden appends.** `find_str` must not add a string; adding is only
  `add_str`. This already holds in `30_syntax.lat`, and the rule must be kept.
* **State reset belongs to the driver.** `90_driver.lat` initializes the slots
  (`set(0, ...)`, `set_ncls(0)` …). Parts must not rely on "memory was zero":
  on a second run in the same instance that is false.

## 4. Errors as an explicit channel

An error is an effect too, but it has a single channel for the whole compiler:

1. `status` (slot 4) is set to `1`;
2. the text is written to `ERRB` in the format `[len u32 LE][utf8]`;
3. the driver checks `status` **after every phase** and returns a negative
   length rather than invalid WASM.

Rules:

* do not swallow `err()`: if a function may fail to find an entity, it returns
  `-1`, and the caller decides whether that is an error;
* do not write to `ERRB` directly from arbitrary places; use
  `tcerr_msg`/`tcerr`/`err_named`;
* do not use `0` for "no error, but no result either": `-1` is for lookup,
  `status` is for errors;
* error text is part of observable behavior (tests compare stage1 and stage2
  character by character). When you change the text, update the tests.

## 5. Size and decomposition

* **File ≤ 300 lines** is a hard requirement (checked in review and in
  `decomposition-plan.md`).
* **Function ≤ 40–50 lines** is a soft requirement. If a function is longer,
  extract a named helper by responsibility, not "so that it fits". Exceptions
  are byte-body generators (`helper_*`), where the length is dictated by the
  WASM format; they must be split into helpers and commented.
* **One part, one responsibility.** The boundaries: lexer, syntax (cursor /
  locals / strings), class, enum, lambda (scan / emission), emit (core / calls /
  host / float / primary / postfix / match / operators), typecheck (core /
  expressions / patterns / instructions / program), stmt (core / host), func,
  module (helpers / conversions / sections), driver.
* **No duplication.** Shared predicates (`is_ident_kind`, `name_eq`, `is_lit`,
  `tok_kind`, `tok_val`) and tables exist in a single instance. If logic repeats
  in two parts, move it into a shared part instead of copying it.
* **Part order is for readability only.** In Latent, functions can be called
  before they are declared: `scan_signatures` and `tc_register` collect all
  signatures in advance. So sorting names does not affect semantics; a new file
  takes a number from its band (00–09 ABI, 10–19 buffer, 20–29 lexer, 30–34
  syntax, 35–39 class/enum/lambda, 40–49 emit, 45–49 typecheck, 50–59 stmt,
  60–69 func, 70–79 module, 90 driver).

## 6. Names and comments

* Identifiers are **English**, comments and documentation are **Russian**,
  UTF-8 without BOM.
* Prefixes:

| Prefix | Meaning |
|---|---|
| `emit_`, `ev_` | emission of bytes/instructions (effect) |
| `b*` (`bput`, `bleb`, `bcopy`, `binit`) | byte-buffer operations (effect) |
| `add_`, `set_`, `scan_`, `register_` | writing to a table/state (effect) |
| `find_`, `get_`, `is_`, `*_len`, `*_tp` | reading (query) |
| `st_` | a statement |
| `tc_` | the type checker |
| `level_`, `parse_` | expression parsing |
| `helper_` | the body of a runtime helper in the output module |

* A comment explains **why** and the **format** (stride, layout, byte order),
  not a retelling of the code.
* Every new memory slot gets a comment in `00_abi.lat` with its address, size,
  and meaning.

## 7. Where imperative code is unavoidable, and why

Fully pure code is impossible in this subset; below are the places where
imperative code is **allowed and expected**, and how to isolate it.

1. **Linear memory is the only data structure.** There are no value arrays,
   structs, or garbage collector: tables are `store32`/`load32` at fixed
   addresses. Isolation: access only through the `00_abi.lat` accessors; the
   other parts do not know numeric addresses.
2. **Buffers and LEB128.** `bput`/`bleb`/`bcopy` must mutate the length and the
   bytes; this is an append-only structure. Isolation: `10_buffer.lat`; no other
   part needs to know about `[len][bytes]`.
3. **WASM emission.** Byte order is the semantics of the module. Isolation:
   `40*_emit_*` and `70*_module_*`; the effect is visible from the name.
4. **The parser cursor.** `get(0, PC)`/`next_token()` is unavoidable parse
   state. Isolation: `30_syntax` and `45a..45d_tc_*`; the `tok_kind`/`tok_val`
   queries are pure.
5. **Registration passes.** `scan_classes`, `scan_enums`, `scan_lambdas` fill the
   tables; they are imperative by definition, but they must not be called again
   without resetting the counters (the driver does that).
6. **Performance and bootstrap constraints.** The compiler compiles itself;
   extra abstractions (lambdas, indirect calls, generics) can slow it down or
   break the fixed point. Prefer direct calls and explicit parameters.

## 8. Relation to the current code

`shc.lat` is a procedural compiler: tokens in parallel arrays, tables in linear
memory, passes `tokenize → scan_* → tc_* → compile_* → build_module`. Rewriting
it in a "pure" style is unnecessary and dangerous for the fixed point.

Practical steps we take:

1. **Boundaries, not a revolution.** New functions are pure queries or explicit
   effects; we bring old ones into line as decomposition proceeds.
2. **We split mixed functions.** Example: instead of `find_or_add_str` we use
   `find_str` + `add_str` (already the case).
3. **We name the sinks.** `emit_*` writes only to the current buffer; `helper_*`
   writes the helper body; `build_module` writes the sections.
4. **We document the slots.** Any new table is a row in the `00_abi` map and a
   comment with its layout.
5. **We check the fixed point after every step.** Any refactoring that changes
   emission must pass `node selfhost/build.mjs`,
   `node selfhost/bootstrap.mjs` (`FIXED POINT`), and the whole selfhost suite.

## 9. Code review checklist

- [ ] File ≤ 300 lines; a function is usually ≤ 50 lines.
- [ ] The function name matches its category (`find_`/`get_`/`is_` are queries;
      `emit_`/`add_`/`set_`/`scan_` are effects).
- [ ] Pure queries do not write to memory and do not move the cursor.
- [ ] No numeric addresses outside `00_abi.lat`; a new slot is documented
      (address, size, stride, owner).
- [ ] No hidden global mutations: state only through `get`/`set` and the named
      tables.
- [ ] Errors go to `status`/`ERRB` and are not swallowed; `err()` is checked by
      the caller/driver.
- [ ] No duplicated logic: shared predicates and tables are reused.
- [ ] Emission order is not changed without a differential test and a
      `stage2 === stage3` check.
- [ ] New tests are differential (oracle vs stage1 vs stage2) and/or atomic;
      coverage does not drop.
- [ ] Comments are in Russian, identifiers in English, UTF-8 without BOM.
- [ ] No dead code and no unused slots.
- [ ] `node selfhost/build.mjs && node selfhost/bootstrap.mjs` — `FIXED POINT`.
- [ ] `node --test "selfhost/test/*.test.mjs"` — green.
- [ ] `node tooling/selfhost-coverage/run.mjs --min 90` — function coverage ≥ 90%.

## 10. Metrics and commands

```bash
# build and fixed point
node selfhost/build.mjs
node selfhost/bootstrap.mjs          # expects FIXED POINT: stage2 === stage3

# regression
node --test "selfhost/test/*.test.mjs"

# function coverage (and, with --lines, approximate instruction coverage)
node tooling/selfhost-coverage/run.mjs --min 90
node tooling/selfhost-coverage/run.mjs --lines
```
