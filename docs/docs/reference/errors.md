# Диагностики

В Latent **нет кодов ошибок** (нет `E0123`): диагностика — это строка на
русском языке (движок №2) или на английском (движок №1), в которую встроена
позиция `L:C` (нумерация с 1). Формат движка №2:

- лексер/парсер: `... на строке L:C`;
- тайпчекер: `... на строке L:C: <подробности>`;
- кодоген: **без позиции** (только текст).

`compile_source` (`src/lib.rs`) возвращает первую ошибку лексинга/парсинга; если
лексер и парсер прошли, собираются **все** ошибки тайпчекера и склеиваются через
`"; "`. Кодоген возвращает первую ошибку.

Исходный каталог в machine-readable виде:
`tooling/language-data/language.json` → `diagnostics`.

## Лексер

Источник: `src/lexer/error.rs`.

| Текст (точно) | Причина | Как исправить |
|---|---|---|
| `Неожиданный символ '<ch>' на строке L:C` | символ не может начинать токен (`#`, `$`, `?`, `~`, ...) | убрать/заменить символ; проверить, что используются только операторы языка |
| `Незавершённая строка на строке L:C` | строка не закрыта до `\n`/EOF | закрыть `"`; переводы строк внутри литерала запрещены |
| `Неверная escape-последовательность '<\X>' на строке L:C` | escape не из `\n \t \\ \"` | использовать только эти четыре |
| `Неверный формат числа '<текст>' на строке L:C` | экспонента без цифр (`1e`, `1e+`) | дописать цифры или убрать `e` |
| `Незавершённый блочный комментарий на строке L:C` | нет закрывающего `*/` | закрыть комментарий (вложенность учитывается) |

Движок №1 на те же ситуации отвечает английским:

- `Unexpected character '#' at line N` — неизвестный символ. Дополнительно:
  `&`, `|`, `^`, `<`, `>` в неподходящем месте им не лексируются как операторы.
- `Unexpected token '...' at line N`, `Expected ) but got '...' at line N` —
  ошибки парсера (см. ниже).

## Парсер

Источник: `src/parser/error.rs`. В сообщение подставляется **Debug-имя
токена**, а не лексема: `Semicolon`, `RBrace`, `Dot`, `Assign`, `BitOr`,
`If`, `Identifier("x")`, `Number(2.0)`, `String("...")`.

| Текст (точно) | Причина | Как исправить |
|---|---|---|
| `Ошибка парсинга на строке L:C: ожидалось '<ожидаемое>', найдено <Токен>` | неожиданная конструкция | смотреть `found` (имя токена) и место |
| `Неожиданный конец файла: ожидалось '<ожидаемое>'` | файл оборван (обычно незакрытая `{`/`(`) | дописать закрывающие скобки |
| `Неверная цель присваивания на строке L:C` | слева от `=` не имя/индекс/поле (например `1 = 2`) | присваивать переменной, элементу или полю |

Типичные примеры:

| Код | Диагностика |
|---|---|
| `fn main() { let x = ; }` | `... ожидалось 'expression', найдено Semicolon` |
| `fn main() -> int { return 1 }` | `... ожидалось ';', найдено RBrace` |
| `let x: int | null = 1;` | `... ожидалось '=', найдено BitOr` (union-типов нет) |
| `x /= 2;` | `... ожидалось 'expression', найдено Assign` (нет `/=`) |
| `let t: Tensor<[2,3]> = ...` | `... ожидалось 'identifier', найдено Number(2.0)` — в generic-аргументах `[2,3]` не тип |
| `let a = 1..2;` | `... ожидалось 'identifier', найдено Dot` |

Движок №1: `Expected <T> but got '<значение>' at line N`,
`Unexpected token '<значение>' at line N`, `Expected decorator name at line N`,
`Invalid type annotation at line N`.

## Тайпчекер

Источник: `src/typechecker/types/mod.rs` (Display), плюс проверки в
`src/typechecker/infer/*`.

| Текст (точно) | Причина | Как исправить |
|---|---|---|
| `Неопределённая переменная '<имя>' на строке L:C` | имя не объявлено (или это `ai`, `break`, `this` вне метода, неизвестная функция в выражении) | объявить переменную/функцию; проверить опечатку |
| `Несовпадение типов на строке L:C: ожидалось '<T1>', найдено '<T2>'` | унификация не удалась | привести типы; помните, что `int`↔`float` совместимы, а `null` — нет |
| `Бесконечный тип на строке L:C: '<$Tn>' = '<T>'` | occurs-check (например `let f = fn(x) => f(x);`) | убрать самоприменение/перестроить рекурсию |
| `Несовпадение арности на строке L:C: ожидалось N аргументов, найдено M` | вызов функции с другим числом аргументов | поправить вызов/сигнатуру |
| `Не функция на строке L:C: тип '<T>'` | вызов у значения не-функции, `await` у не-`Promise` и т.п. | поправить тип/выражение |
| `Отсутствует return на строке L:C` | **зарезервировано**, в v0.1.0 не порождается | — |
| `Неверный AI-тип на строке L:C: <сообщение>` | **зарезервировано**, в v0.1.0 не порождается | — |

Особенности:

- Для `if (1)` вы получите `Несовпадение типов ...: ожидалось 'float', найдено
  'bool'` — «обратный» порядок: `expected` — левая часть унификации (тип
  условия), `found` — правая (`bool`). Это не ошибка текста, а следствие
  реализации `unify(t_cond, Bool)`.
- Ошибки арности и «не функция» приходят из унификации `Fn`, поэтому позиция
  может указывать на имя вызываемой функции, а не на аргумент.
- `for (let x in "строка")` — ошибка типов: итерабельное должно быть массивом;
  сообщение вида `Несовпадение типов ...: ожидалось 'string', найдено '[$T5]'`.
- `await` у не-`Promise`: `... ожидалось 'Promise<$T6>', найдено 'float'`.
- Тайпчекер сообщает обо всех ошибках сразу (склейка `"; "`), но после первой
  ошибки в конкретном выражении может потерять контекст.

### Что тайпчекер НЕ ловит

Многие ошибки проявляются только в кодогене или в рантайме: операнды
арифметики/сравнений, типы полей объектов, сигнатуры методов (кроме каналов),
гомогенность массивов, `null`-безопасность. Полный список —
[типы → что typechecker игнорирует](./types.md#что-typechecker-игнорирует).

## Кодоген

Источник: `src/codegen/`. Эти сообщения **без позиции**.

| Текст (точно) | Причина |
|---|---|
| `Unknown function: <имя>` | вызов имени, которого нет среди функций/builtins/вариантов |
| `Builtin '<имя>' не поддерживается движком №2 (требует host-рантайма)` | host-примитив (`tensor`, `ai_infer`, `channel`, ...) |
| `Метод '<имя>' не поддерживается движком №2 (требует host-рантайма)` | host-метод (`send`, `recv`, ...) или неизвестный метод |
| `Undefined variable: <имя>` | имя не найдено среди локальных (часто — обращение к top-level `let` или вложенной `fn`: они не компилируются) |
| `Unknown field: <Class>.<field>` | поля нет в layout класса |
| `Unknown class: <имя>` | класс не объявлен (в т.ч. `arr.len` — трактуется как поле неизвестного класса) |
| `Unknown enum variant: <имя>` | конструктор не объявлен и не встроенный |
| `Enum variant '<имя>' expects N field(s), got M` | неверная арность конструктора |
| `Enum pattern '<имя>' expects N field(s), got M` | неверное число под-паттернов |
| `Unsupported literal pattern in match codegen` | паттерн-литерал неподдерживаемого вида (например `null`) |
| `Complex assignment not yet supported` | присваивание во вложенную цель |
| `Оператор отправки в канал (ch <- v) требует host-рантайма движка №1` | `<-` send |
| `Приём из канала (<- ch) требует host-рантайма движка №1` | `<-` recv |
| `AI-примитивы требуют host-рантайма движка №1` | `ai_generate!`, AI-узлы AST |
| `push expects (array, value)` | функциональный `push` без 2 аргументов |
| `internal: lambda not hoisted` | внутренняя ошибка регистрации лямбды |

Движок №1 (английский, рантайм): `Undefined function 'x'`, `Undefined variable
'x'`, `Unknown method 'x'`, `Unknown class 'x'`, `Unknown field`, `Function
'main' not found`, `assertion failed`, `assert_eq failed: a != b`,
`Deadlock: ...`, `Loop iteration limit exceeded`, `AI is not enabled. Use
"Compile & Run with AI" button.`, `Unable to send on closed channel`,
`Value is not iterable: ...`, `match: no arm matched value ...`.

## Ошибки self-hosted компилятора

`selfhost/shc.lat` при ошибке возвращает отрицательное число, а по адресу
`OUTPUT_ADDR+4` (65536+4) кладёт `[len u32][utf8-текст]`. Тексты формирует
сам компилятор (`selfhost/src/45a_tc_core.lat` и остальные части `45*`, буфер
`ERRB`), они короче Rust-диагностик; для паритета ориентируйтесь на
`selfhost/test/*.test.mjs` и [specs/selfhost](../specs/selfhost.md).

## Диагностики кодогена и ограничения движка №2

Кодоген (`src/codegen/`) **не проверяет типы**: он выбирает инструкции по
синтаксической оценке (`StaticTy`), а слоты локальных — по аннотации, без
приведений. Поэтому часть программ компилируется «успешно» (status=1), но
`WebAssembly.validate()` для результата даёт `false`. Это **честное описание
текущего поведения**: такие конструкции нельзя использовать как рабочие.

### Известные ограничения движка №2 (компилируется, но невалидный WASM)

| Класс случая | Пример | Почему |
|---|---|---|
| float-литералы с нулевой дробной частью | `fn main() -> float { return 5.0; }`, `1e3` | литерал `5.0` → `i32.const`, сигнатура `f64` |
| float-деление целочисленных литералов | `7.0 / 2.0` | оба литерала `fract==0` → `i32.div_s` |
| `let` с аннотацией «другого» типа | `let x: int = 1.5;`, `let x: float = 2;` | слот по аннотации, значение другого valtype |
| массивы с float | `let a = [1.5, 2.5];`, `a[0] = 1.5` | элементы пишутся `i32.store` |
| смешанная float/int арифметика | `1 + 2.5` | левый операнд → `i32.const` |
| float-сравнения | `if (1 < 1.5)` | `f64.lt` с i32-операндом |
| `%` на float | `5.5 % 2.0` | всегда `i32.rem_s` |
| `sqrt` вне f64-контекста | `print(sqrt(16))`, `int(sqrt(16))` | `StaticTy::Int` → `i32_to_str`/int-контекст на f64-значении; при `-> float { return sqrt(16); }` — валидно |
| `unit`-возврат с `return;` | `fn f() -> unit { return; }` | сигнатура i32, `return` без значения |
| void-вызов как значение | `let x = print("a");` | `local.set` без значения |
| float-поля/float-параметры классов | `class P { v: float; fn init(a: float) {…} }` | f64 в i32-сигнатуре метода |
| захват float лямбдой | `let x = 1.5; let f = fn() => x;` | захват пишется `i32.store` |
| `match` с void-ветками | `match 1 { case 1: print(1), default: print(0) };` | `if` ожидает i32-результат |
| присваивание float в int-слот | `let x = 1; x = 2.5;` | слот i32, значение f64 |
| float-аргумент в int-параметр | `fn f(x: int) -> int {…} f(1.5)` | приведения нет |
| float-payload enum | `enum E { A(float) } A(1.5)` | payload пишется `i32.store` |
| `new Class(...)` без `init` в достижимом коде | `class A {x:int;} let a = new A(5);` | лишние значения на стеке |
| void-метод в позиции инструкции | `class B { fn set(v) { this.value = v; } } b.set(42);` | `expr_produces_value` не распознаёт методы → `drop` после void-вызова |

Практическое правило: **float работает только там, где и слот, и все операнды
синтаксически «дробные»**: `let x = 1.5; let y = 2.5; x + y` → `4.0`,
`print(1.5)` → `1.500000`, `fn f() -> float { return 2.5; }` — валидны.
Целочисленно-значные float-литералы (`2.0`, `5.0`) ломают f64-контекст.

### Прочие дефекты, важные для документации

| Что | Наблюдение |
|---|---|
| `pop()` на пустом массиве | читает `arr[-1]` — порча памяти, без диагностики |
| `push` на строке | компилируется и пишет в строку |
| `assert`/`assert_eq` с сообщением | второй аргумент игнорируется |
| `len()` без аргумента | читает память по адресу 0 (обычно `0`) |
| дубликаты `fn` | не диагностируются, последняя сигнатура/тело перетирает |
| `obj.length` перехватывается раньше полей класса | `p.length` читает заголовок памяти, а не поле `length` класса |
| `this` вне метода | `UndefinedVariable`; при этом `infer_class_name` для `this` без класса берёт первый попавшийся класс (эвристика) |
| `for` C-стиль с не-bool условием | не диагностируется |
| `return` внутри `spawn` | возвращает из объемлющей функции |
| `return` внутри ветки `match` | не парсится (ветка — выражение) |
| `f64_to_str` для больших чисел | целая часть через `i32.trunc_f64_s`; `|x| ≥ 2^31` — trap; `str(1e300)` не работает |
| `i32_to_str` для `i32::MIN` | `0 - n` переполняется |
| строки в `< > <= >=` | сравниваются указатели, не содержимое |
| `assert_eq` строк/массивов | сравниваются i32-значения: литералы могут совпасть (дедупликация), результат конкатенации — trap |
| escape-последовательности | только `\n \t \\ \"`; `\r`, `\0`, `\u{...}` — ошибка |
| деление/остаток на 0 | WASM-trap; `i32::MIN / -1` — trap |
| арность builtins | не проверяется: лишние аргументы молча игнорируются (`assert`, `len`, `str`, …) |
| BOM в начале файла | lexer не пропускает `U+FEFF`: ошибка с колонкой `4294967295` (переполнение), а debug-сборка `latentc` падает (panic) |
| лишние значения на стеке | обнаруживаются только `WebAssembly.validate()` у хоста |

### Оформление таких примеров в документации

`docs/scripts/validate-examples.mjs` считает блок «ожидаемо невалидным», если
первая непустая строка — `// ошибка: ...` / `// Не компилируется движком №2:
...`, либо в info-string есть `expected-error`. Так помечаются примеры
host-only и примеры из таблицы выше. Не помечайте рабочие примеры: валидатор
сообщит «устаревший маркер».

## Как читать диагностику

1. Позиция `L:C` — 1-based, столбец считается в символах (не байтах).
2. Если сообщение без позиции — это кодоген; ищите в тексте имя функции/поля.
3. Несколько ошибок через `; ` — все от тайпчекера.
4. Текст ошибки возвращается как есть в буфер `latent_compile` (status=0) —
   в IDE это то, что вы видите в консоли.
