# Грамматика

Грамматика ниже восстановлена **по коду парсера**
(`src/parser/`: `declarations.rs`, `statements.rs`, `expressions/`,
`type_parser.rs`). Это не академическое описание, а контракт: всё, что здесь
есть, парсер действительно принимает. В конце — таблица приоритетов и список
«парсится, но дальше не работает».

Обозначения EBNF: `{ x }` — ноль или более повторений, `[ x ]` — необязательно,
`x | y` — альтернатива, `"..."` — терминал.

## Программа и объявления

```ebnf
Program        ::= { Declaration } EOF

Declaration    ::= Decorator
                 | TestDeclaration
                 | LetDecl
                 | AsyncFnDecl
                 | FnDecl
                 | ClassDecl
                 | EnumDecl
                 | Statement

Decorator      ::= "@" Name [ "(" [ Expr { "," Expr } ] ")" ] Declaration
TestDeclaration::= "test" ( String | [ "(" ] String [ ")" ] ) Block
LetDecl        ::= "let" Ident [ ":" Type ] "=" Expr ";"

FnDecl         ::= "fn" ( Ident | SoftKeyword ) "(" [ Params ] ")" [ "->" Type ] Block
AsyncFnDecl    ::= "async" "fn" ...            (* то же, что FnDecl, с is_async *)

Params         ::= Param { "," Param }
Param          ::= Ident [ ":" Type ]

ClassDecl      ::= "class" Ident "{" { ClassMember } "}"
ClassMember    ::= FnDecl
                 | ( Ident | SoftKeyword ) [ ":" Type ] ";"

EnumDecl       ::= "enum" Ident "{" [ Variant { "," Variant } [ "," ] ] "}"
Variant        ::= Ident [ "(" [ Type { "," Type } ] ")" ]
```

Примечания к объявлениям:

- Парсер не различает «верхний уровень» и «блок»: **внутри** `{ ... }`
  используется тот же `parse_declaration`, поэтому `fn`, `class`, `enum`,
  `test`, `@decorator` синтаксически допустимы внутри функции. Кодогенератор
  при этом вложенные `fn`/`class`/`enum` **молча игнорирует**
  (`src/codegen/emit_stmt.rs`, ветка `_ => Ok(())`).
- `TestDeclaration` распознаётся по префиксу `test` + строковый литерал, в том
  числе с необязательными скобками: `test("name") { ... }` и
  `test "name" { ... }`.
- Имя функции может быть «мягким» ключевым словом (`fn model()`), но не твёрдым.
- `Params`: имя параметра — обычный идентификатор, `this` параметром класса
  указывать не нужно (он добавляется кодогеном неявно, см.
  [внутреннее устройство кодогена](../specs/internals-codegen.md)).
- Разделитель в списках параметров/вариантов/полей — запятая; «висячая»
  запятая в enum разрешена (как и в аргументах вызовов, и в элементах массива
  — циклы разбора завершаются по виду токена).
- `Decorator` навешивается на любое объявление: `@forall("array") fn f(...)`,
  `@ai_contract("sorting") fn g(...)`, `@test("x") fn h(...)`.

## Инструкции

```ebnf
Block          ::= "{" { Declaration } "}"

Statement      ::= IfStmt | WhileStmt | ForStmt | ReturnStmt | SpawnStmt
                 | MatchStmt | SelectStmt | YieldStmt | ExprStmt

IfStmt         ::= "if" "(" Expr ")" Block [ "else" ( Block | IfStmt ) ]
WhileStmt      ::= "while" "(" Expr ")" Block

ForStmt        ::= "for" "(" ForCForm ")" Block
                 | "for" "(" "let" Ident [ ":" Type ] "in" Expr ")" Block
ForCForm       ::= [ LetDecl | Expr ";" ] ";" [ Expr ] ";" [ Expr ]

ReturnStmt     ::= "return" [ Expr ] ";"
SpawnStmt      ::= "spawn" ( Block | Expr ) [ ";" ]
MatchStmt      ::= MatchExpr ";"
SelectStmt     ::= "select" "{" { SelectArm } [ DefaultArm ] "}" [ ";" ]
SelectArm      ::= [ "case" ] [ Ident ] "<-" Expr ":" Block
DefaultArm     ::= [ "case" ] "default" ":" Block

YieldStmt      ::= "yield" ";"
ExprStmt       ::= Expr ";"
```

Примечания к инструкциям:

- **Условия всегда в скобках**: `if (x)`, `while (x)`, `for (...)`; вариант без
  скобок не принимается.
- `else if` реализован рекурсией: `else` + `if` → вложенная инструкция `if`.
- `for` имеет две формы. C-стиль: `for (let i = 0; i < n; i = i + 1)`,
  причём `init` может быть `let`, присваиванием/выражением или пустым
  (`for (; i < n; )`); `cond` и `step` тоже необязательны. Форма обхода:
  `for (let x in arr)`; тип у переменной можно указать, но он парсится и
  **отбрасывается** (переменная получает тип элемента итерабельного).
- `spawn` принимает либо блок `spawn { ... }`, либо выражение
  (`spawn worker(args)`); выражение оборачивается в одну инструкцию-
  выражение и выполняется как «горутина».
- `match` в позиции инструкции — это match-выражение + обязательная `;`.
- `select` — отдельная инструкция. `case` необязателен (принимается и
  `case v <- ch:`, и `v <- ch:`); ветка `default` необязательна. Тело ветки —
  обязательно блок `{ ... }` для инструкции; для select-выражения тело —
  выражение.
- `yield;` — точка с запятой обязательна.
- Выражение-инструкция требует `;`. Присваивание — это выражение, поэтому
  `x = 1;` тоже выражение-инструкция.

## Выражения

Выражения разбираются Pratt-парсером (`src/parser/expressions/core.rs`).

```ebnf
Expr           ::= Prefix { InfixOp Expr | Postfix }

Prefix         ::= Number | String | "true" | "false" | "null"
                 | Ident | SoftKeyword
                 | "ai"                                  (* идентификатор "ai" *)
                 | "channel" [ "<" Type ">" ] "(" [ Args ] ")"
                 | "async" | "this" | "assert"
                 | "new" Ident
                 | "-" Expr | "!" Expr | "<-" Expr | "await" Expr
                 | "(" Expr ")"
                 | "[" [ Expr { "," Expr } ] "]"
                 | Lambda | MatchExpr | SelectExpr
                 | "ai_generate" "!" "(" String ")"

Lambda         ::= "fn" "(" [ Params ] ")" ( "->" Type )? ( "=>" Expr | Block )
MatchExpr      ::= "match" Expr "{" { MatchArm } "}"
MatchArm       ::= [ "case" ] Pattern ":" Expr [ "," ]
SelectExpr     ::= "select" "{" { SelectExprArm } [ DefaultExprArm ] "}"
SelectExprArm  ::= [ "case" ] [ Ident ] "<-" Expr ":" Expr [ "," ]
DefaultExprArm ::= [ "case" ] "default" ":" Expr [ "," ]

Pattern        ::= "_"
                 | Number | String | "true" | "false" | "null"
                 | Ident [ "(" [ Pattern { "," Pattern } ] ")" ]
                 | "default"

InfixOp        ::= "=" | "<-" | "||" | "&&" | "==" | "!="
                 | "<" | ">" | "<=" | ">=" | "|" | "^" | "&"
                 | "<<" | ">>" | "+" | "-" | "*" | "/" | "%"
Postfix        ::= "(" [ Args ] ")" | "[" Expr "]" | "." Ident
Args           ::= Expr { "," Expr }
```

Примечания к выражениям:

- **`new Class(...)` не является специальным узлом парсера**: `new` разбирается
  как идентификатор с пробелом — `Identifier("new Class")`, а вызов
  `(...)` — обычный постфикс. Отсюда правила: класс обязан идти сразу после
  `new`, аргументы — обычный список.
- **`channel<int>()`**: `channel` — ключевое слово, поэтому разбирается особой
  ветвью; аргументы типа (`<int>`) парсятся и отбрасываются; результатом
  является вызов функции с именем `channel`.
- **`ai`** в позиции операнда становится идентификатором `"ai"`; `ai.load(...)`,
  `ai.infer(...)`, `ai.agent(...)` синтаксически выглядят как вызовы методов у
  значения с именем `ai`, но такой переменной нет — typechecker выдаст
  «Неопределённая переменная 'ai'». (В AST есть узлы `AiLoad/AiInfer/AiAgent`,
  но парсер их не создаёт — см. ниже.)
- **`ai_generate!("prompt")`** — единственный AI-примитив с особой ветвью
  парсера (`ExprKind::AiGenerate`); аргумент обязан быть строковым литералом.
- `assert` — особый токен в позиции префикса, становится идентификатором
  `assert`. `assert_eq` — мягкое ключевое слово, тоже становится
  идентификатором. Оба «вызова» разбираются как обычные вызовы.
- Лямбда: `fn(x) => expr` или `fn(x) { ... }`; после `)` можно указать тип
  возврата (`fn(x) -> int { ... }`). Параметры лямбды допускают аннотации.
  Свободные переменные лямбды вычисляются парсером лексически и сохраняются в
  `locals` (используются кодогеном для замыканий).
- `match` — выражение; ветки разделяются запятыми, `case` и финальная запятая
  необязательны. `default:` — синоним `_` (wildcard). Тело ветки может быть
  блоком `{ ... }`.
- `select` бывает инструкцией и выражением; в выражении значение — результат
  тела выигравшей ветки.
- Скобки вокруг выражения — обычная группировка; отдельного «кортежа» нет
  (хотя в системе типов есть `Tuple`, парсер его не создаёт).
- `1 < 2 < 3` парсится как `(1 < 2) < 3` (левая ассоциативность сравнений).

## Типы в аннотациях

```ebnf
Type           ::= "fn" "(" [ Type { "," Type } ] ")" "->" Type
                 | "[" Type "]"
                 | "channel"                                  (* встроенный тип канала *)
                 | Name [ "<" [ Type { "," Type } ] ">" ]
Name           ::= Ident | SoftKeyword
```

Особенности (`src/parser/type_parser.rs`):

- внутри `<>` допускаются идентификаторы типов **и числовые литералы**:
  `Tensor<2, 3>` разберётся, число станет `Type::Named("2")`. А вот
  `Tensor<[2, 3]>` — **нет**: `[` ожидает тип, `Number` типа не начинает.
- `channel` как аннотация — специальная ветка, результат `Type::Named("channel")`.
- **union-типов в грамматике нет**: конструкции `int | null` в аннотации не
  существует, хотя `ast::Type::Union` и `LatentType::Union` определены
  (в AST они никогда не создаются парсером).
- `void`/`unit` разбираются как обычные имена (это не ключевые слова лексера),
  а typechecker отображает оба в `Type::Unit`.

## Таблица приоритетов (Pratt)

Числа — binding power из `src/parser/expressions/core.rs`
(`(left_bp, right_bp)`; чем больше, тем «крепче»). Левая ассоциативность:
`right_bp = left_bp + 1`.

| Приоритет | Оператор | Ассоц. | Примечание |
|---:|---|---|---|
| 2 | `=` (присваивание) | правая | цель: имя, `a[i]`, `o.f` |
| 2 | `<-` (отправка в канал) | правая | host-only |
| 10 | `\|\|` | левая | короткое замыкание |
| 20 | `&&` | левая | короткое замыкание |
| 30 | `==`, `!=` | левая | в движке №2 для строк — побайтовое сравнение |
| 40 | `<`, `>`, `<=`, `>=` | левая | |
| 50 | `\|`, `^` | левая | побитовые |
| 60 | `&` | левая | побитовое |
| 70 | `<<`, `>>` | левая | сдвиги |
| 80 | `+`, `-` | левая | `+` над `string` — конкатенация |
| 90 | `*`, `/`, `%` | левая | |
| 95 | префиксные `-`, `!`, `<-`, `await` | правая | `parse_expression(95)` |
| 100 | постфиксные `()`, `[]`, `.` | левая | вызов/индекс/поле |

Следствие: `1 | 2 + 3` = `1 | (2 + 3)`; `a && b == c` = `a && (b == c)`;
`-x * y` = `(-x) * y`; `a = b = c` = `a = (b = c)` (и это допустимо: результат
присваивания — значение, см. [операторы](./operators.md)).

## Что парсится, но дальше не работает

Это важный раздел: грамматика шире, чем рабочая семантика. Ниже — конструкции,
которые парсер принимает, но компилятор/typechecker отвергает или игнорирует.

| Конструкция | Что происходит |
|---|---|
| union-тип `int \| null` | **не парсится** (нет продукции) → ошибка «ожидалось '=', найдено BitOr» |
| tuple `(int, int)` в типе | не парсится (скобки трактуются как группировка/параметры `fn`) |
| `ai`-объявления (`ai model ...`, `AiLoad`) | AST/typechecker/codegen поддерживают узлы, но парсер их **не создаёт** |
| `ai` как значение | идентификатор `"ai"` → «Неопределённая переменная 'ai'» |
| `ai.infer/ai.load/ai.agent` | вызовы метода у несуществующей переменной `ai` → та же ошибка |
| вложенные `fn`/`class`/`enum` в теле | парсятся, typechecker их типизирует, кодоген **игнорирует** |
| `break`/`continue` | идентификаторы → «Неопределённая переменная 'break'» |
| `if` как выражение | не парсится (в позиции выражения `if` недопустим) |
| `let x = if (...) ...` | ошибка «ожидалось 'expression', найдено If» |
| `try/catch`, `switch`, циклы со скобками без `()` | отсутствуют |
| statement без `;` для `let`/`return`/вызова | ошибка «ожидалось ';'» (в движке №1 часто допустимо) |
| `x += 1`, `++x` | не существуют (лексер не знает таких операторов) |
| `spawn` блока/вызова | парсится; в движке №2 исполняется последовательно, в №1 — планировщик |
| `select` по каналам | парсится; в движке №2 исполняется **тело первой ветки** (или default) без ожидания |
| `await` | парсится; в движке №2 — прозрачное разворачивание значения |
| `channel()` | парсится; в движке №2 — ошибка «Builtin 'channel' не поддерживается…» |
| `@decorator fn f(...)` / `@decorator class C` | парсится, но цель декоратора **не регистрируется** сканером функций/классов: вызов `f(...)`/`new C(...)` даст `Unknown function` |
| `test "name" { ... }` на верхнем уровне | парсится, типизируется, но тело не эмитится (раннера нет) |

## Грамматика движка №1 (отличия)

Движок №1 (`web-ide/compiler/parser*.js`) разбирает почти то же подмножество, но
с отличиями, которые важны для IDE:

- точка с запятой в большинстве инструкций **необязательна**;
- поддерживаются только операторы `+ - * / %`, `== != < <= > >=`, `&& || !`,
  `-> => <-`, ` = `; побитовых `& | ^ << >>` нет (лексер падает на `&`);
- `for (;;)` без `let` в начале не поддерживается; форма `for (let x in ...)`
  есть;
- `a = b = c` не поддерживается (присваивание — инструкция, не выражение);
- `let x = if (...) ...` не поддерживается;
- нет блочных комментариев `/* */`;
- аннотации типов разбираются, но не проверяются и отбрасываются;
- `enum` не поддерживается вовсе (лексер/парсер не знают такого объявления).
