# WASM ABI

Источники: `src/codegen/module_builder/`, `sections.rs`, `memory.rs`,
`runtime_helpers/`, `emit_lambda.rs`, `emit_enum.rs`, `context.rs`,
`src/lib.rs` (C-ABI компилятора). Модуль собирается вручную байт-в-байт — без
`wasm-bindgen` и без WASI.

## Что импортирует и экспортирует модуль программы

### Импорт

```text
(import "env" "print" (func (param i32)))
```

- Всегда ровно один импорт; он **всегда** добавляется (`WasmCodegen::new` →
  `add_import_print`), даже если `print` не вызывается.
- Импорт занимает **индекс функции 0**, поэтому все пользовательские функции,
  методы, лямбды и рантайм-хелперы сдвинуты на 1.
- Параметр — указатель на строку в линейной памяти в формате
  `[len u32 LE][utf8 bytes]`; хост читает UTF-8 и печатает.

### Экспорты

| Имя | Вид | Когда есть |
|---|---|---|
| `memory` | память | всегда |
| `main` | функция | если в программе объявлена `fn main` |

Сигнатура `main` определяется аннотацией: `fn main() -> int` → `() -> i32`;
`fn main() -> float` → `() -> f64`; функция без аннотации, но с `return expr`
→ `() -> i32`; без `return` — `() -> void`. Хост вызывает `main()` и получает
`i32`/`f64`/`undefined` (`src/codegen/sections.rs`).

Даже если `main` отсутствует, модуль валиден (полезно для библиотек), но
экспорта `main` не будет.

## Секции модуля

Порядок и состав (`emit_sections`):

| ID | Секция | Условие |
|---:|---|---|
| 1 | Type | если есть типы (всегда) |
| 2 | Import | всегда (`env.print`) |
| 3 | Function | если есть функции |
| 4 | Table | **только если есть лямбды**; `funcref`, min = `import_count + func_count` |
| 5 | Memory | всегда: `min = 16` страниц (1 MiB), без max |
| 6 | Global | всегда: одна **mutable i32** — `heap_ptr`, начальное значение `memory_offset` |
| 7 | Export | всегда (`memory`, опционально `main`) |
| 9 | Element | при наличии таблицы: одна active-сегмент-функция на каждый индекс функции (`0..total_funcs`) |
| 10 | Code | если есть тела |
| 11 | Data | если есть строковые литералы |

Секций `start`, `data count`, `custom` нет. Все индексы — u32 LEB128, числа —
signed LEB128 (`ByteBuffer` в `src/codegen/bytecode.rs`).

## Память и аллокатор

- **Страница** — 65 536 байт; **стартовый размер** — 16 страниц (1 МиБ),
  задаётся в `WasmCodegen::new` (`memory_pages: 16`). Секция memory пишет
  только `min` (лимит сверху не задан).
- **Статический слой**: строковые литералы кладутся в data-секцию начиная с
  адреса 1024 (`memory_offset` инициализируется 1024), с дублированием по
  содержимому (`add_string`). Каждый литерал — отдельный active data-сегмент:
  `[len u32 LE][utf8 bytes]`.
- **Куча**: глобальная переменная 0 (`heap_ptr`) инициализируется значением
  `memory_offset` **после** размещения всех строковых литералов (то есть
  `1024 + Σ размеров уникальных литералов`). Куча растёт вверх благодаря
  bump-аллокатору `__latent_alloc`; повторного использования памяти нет.
- **Рост памяти**: `__latent_alloc(size)` увеличивает `heap_ptr` и, если
  `heap_ptr` вышел за `memory.size * 65536`, вызывает `memory.grow` на нужное
  число страниц (`emit_alloc_body`). Ошибки роста (лимит) не обрабатываются —
  при исчерпании памяти модуль получит `-1` от `memory.grow`, который
  отбрасывается (`drop`).

Все multi-byte значения — **little-endian**; `i32.load`/`i32.store` используют
align=2 (4 байта), `f64` — align=3 (8 байт).

## Раскладка данных

### Строка

```text
адрес → [len u32 LE][utf8 байты ...]
```

- `len` — длина в **байтах UTF-8**.
- `len(s)` = `i32.load(s)`; `s[i]` = байт `i32.load8_u(s + 4 + i)` (0..255),
  вне границ — `-1` (хелпер `__latent_str_char_at`).
- Конкатенация (`+`) создаёт новую строку в куче через
  `__latent_str_concat`; сравнение `==` — `__latent_str_eq` (сначала указатели,
  затем длины, затем побайтово).
- Число → строка: `__latent_i32_to_str` (десятичное, со знаком) и
  `__latent_f64_to_str` (фиксированные 6 знаков после точки, например
  `3.140000`). Строка → int: `__latent_str_to_i32` (ASCII, опциональный `-`,
  останавливается на первом нецифровом символе).
- Строковые литералы дедуплицируются в пуле data-секции.

### Массив

```text
адрес → [len u32][elem0 i32][elem1 i32]...
```

- Элемент — всегда 4 байта (`i32`/указатель/`f64`-биты не поддерживаются:
  массив float в движке №2 не типизирован особым образом).
- `arr[i]` = `i32.load(arr + 4 + i*4)`; `a[i] = v` = `i32.store`.
- Литерал `[1, 2, 3]` выделяется в куче (`__latent_alloc(4 + 4n)`), `len`
  записывается в заголовок; `push` пишет по индексу `len` и увеличивает
  заголовок; `pop` уменьшает заголовок и читает элемент.
- `.length`/`len()` — чтение заголовка.
- Массивы передаются по указателю (мутируются на месте); границы не
  проверяются.

### Класс

```text
адрес → [field0][field1]...
```

- Layout вычисляется в `collect_class_layouts`: поле типа `float` занимает 8
  байт (`f64`), **все остальные** — 4 байта (`i32`); выравнивание каждого поля —
  по его размеру (маска), итоговый размер выравнивается по 4.
- Смещения фиксированы, наследования нет.
- Методы не лежат в объекте: `obj.method(args)` компилируется в прямой вызов
  функции `Class_method(obj, args...)` с неявным первым параметром `this`.
  Имена функций манглятся как `Class_method` (например `Point_init`,
  `Point_norm2`).
- `new Class(args)` выделяет `size` в куче, компилирует аргументы, вызывает
  `Class_init`/`Class_new` (если он объявлен) и возвращает указатель.
- Поля по умолчанию — нули (память WASM изначально нулевая, куча не
  переиспользуется), но это не «null-инициализация» в смысле языка.

```latent
class Point {
    x: int;
    y: int;

    fn init(x, y) {
        this.x = x;
        this.y = y;
    }
}

fn main() -> int {
    let p = new Point(1, 2);
    return p.x + p.y;
}
```

### Enum (sum-тип)

```text
n-арный вариант:  адрес → [tag i32][field0 i32][field1 i32]...
0-арный вариант:  значение = сам tag (i32), без выделения памяти
```

- Теги назначаются по порядку объявления вариантов (`0, 1, 2, ...`), встроенные
  `Ok`/`Err`/`Some`/`None` регистрируются заранее (`Ok`=0, `Err`=1, `Some`=0,
  `None`=0 и 0 полей).
- Таблица `enum_variants` **глобальная по имени варианта**, а не по имени enum:
  варианты с одинаковыми именами в разных enum перетирают друг друга.
- Поля пишутся `i32.store` — поэтому enum с `float`-полем даёт невалидный WASM.
- `match` компилируется в цепочку `if/else`: сравнение тега (для 0-арных — с
  самим значением), затем связывание полей.

### Замыкание (лямбда)

```text
closure → [table_slot i32][env_ptr i32]      (8 байт)
env     → [captured0 i32][captured1 i32]...  (4*n байт)
```

- В первом проходе (`collect_lambdas`) каждая лямбда регистрируется как функция
  `__lambda_N` с типом `(env i32, params...) -> i32`.
- При вычислении лямбды создаётся env в куче и closure-пара; захваченные
  переменные копируются в env **по значению**.
- Вызов: `call_indirect` по слоту таблицы; перед вызовом на стек кладутся
  `env, args...`, на вершине — `table_slot`. Тип элемента таблицы —
  `(i32 env, i32...) -> i32`; result всегда `i32` (даже если лямбда возвращает
  float — см. дефекты).
- Таблица функций создаётся только если в программе есть лямбды; element-секция
  кладёт **все** функции модуля с индекса 0 (слот = индекс функции).

### Рантайм-хелперы

Обычные функции модуля (не импорты), эмитятся после пользовательских функций:

| Имя | Сигнатура | Назначение |
|---|---|---|
| `__latent_alloc` | `(i32 size) -> i32` | bump-аллокатор + `memory.grow` |
| `__latent_mem_copy` | `(i32 dst, i32 src, i32 len)` | побайтовое копирование |
| `__latent_str_len` | `(i32 ptr) -> i32` | длина строки |
| `__latent_str_concat` | `(i32 a, i32 b) -> i32` | конкатенация |
| `__latent_str_eq` | `(i32 a, i32 b) -> i32` | сравнение содержимого |
| `__latent_str_char_at` | `(i32 ptr, i32 i) -> i32` | байт по индексу или `-1` |
| `__latent_i32_to_str` | `(i32 n) -> i32` | int → строка |
| `__latent_f64_to_str` | `(f64 n) -> i32` | float → строка (6 знаков) |
| `__latent_str_to_i32` | `(i32 ptr) -> i32` | строка → int |

Эти имена видны в WASM (не экспортируются, вызываются по индексу).

## Порядок индексов функций

1. Индекс `0` — импорт `env.print`.
2. Пользовательские `fn` в порядке объявления.
3. Методы классов (`Class_method`) — в порядке объявления классов/методов.
4. Лямбды (`__lambda_N`).
5. Рантайм-хелперы (в порядке регистрации).

Прибавление пользовательской функции сдвигает индексы только тех сущностей,
которые зарегистрированы позже (как и в любом WASM-модуле); element-секция и
`call_indirect` используют актуальные индексы.

## Значения и соглашения вызова

- Все значения — `i32` (`int`, `bool`, `string`, массивы, объекты, enum,
  замыкания, `null`), кроме `float` — `f64`.
- Функция без аннотации возврата не имеет результата; функция с аннотацией —
  `i32`/`f64` (даже `-> unit`: результат `i32` и `i32.const 0` в конце).
- `void`-вызовы (`print`, `assert`, `assert_eq`, `store8`, `store32`,
  `memcopy`, пользовательские функции без результата, методы без
  `return`-аннотации) не оставляют значения на стеке; в позиции инструкции
  `DROP` для них не эмитится (`expr_produces_value`).
- Параметры функций по умолчанию `i32`, если нет аннотации `float`/`f64`.
- Функция без аннотации, но с `return expr`, получает результат `i32` — даже
  если возвращает float-выражение (дефект).

## C-ABI компилятора (движок №2 в браузере)

Собранный `cargo build --release --target wasm32-unknown-unknown` компилятор
(`web-ide/compiler.wasm`) экспортирует шесть функций (`src/lib.rs`):

| Экспорт | Сигнатура | Назначение |
|---|---|---|
| `latent_alloc` | `(i32 size) -> i32` | выделить буфер из Rust-`Vec` (утечка до `latent_free`) |
| `latent_compile` | `(i32 src_ptr, i32 src_len) -> i32` | скомпилировать **один** исходник из линейной памяти |
| `latent_compile_files` | `(i32 manifest_ptr, i32 manifest_len) -> i32` | скомпилировать проект из манифеста `LPF1` |
| `latent_bundle_files` | `(i32 manifest_ptr, i32 manifest_len) -> i32` | собрать плоский Latent-исходник проекта (`bundle`) |
| `latent_free` | `(i32 ptr, i32 size)` | освободить буфер (`Vec::from_raw_parts(ptr, 0, size)`) |
| `latent_version` | `() -> i32` | вернуть буфер с версией |

Формат буфера ответа `latent_compile` (и обеих модульных функций):

```text
[status u32 LE][len u32 LE][payload: len байт]
status = 1 → payload это .wasm-байты (у latent_bundle_files — UTF-8 исходник)
status = 0 → payload это UTF-8 сообщение об ошибке
```

Формат буфера `latent_version`:

```text
[len u32 LE][utf8: "latent 0.1.0"]
```

Порядок использования (см. `web-ide/compiler/wasm-loader.js`):

1. `ptr = latent_alloc(len)`;
2. записать исходник в `memory[ptr..ptr+len]`;
3. `res = latent_compile(ptr, len)`;
4. прочитать `status`/`len`/`payload` по `res`;
5. освободить оба буфера `latent_free`.

Модуль компилятора инстанцируется без импортов (`WebAssembly.instantiate(bytes,
{})`); это чистый `wasm32-unknown-unknown`-модуль.

### Модульный ABI: манифест `LPF1`

`latent_compile_files` и `latent_bundle_files` принимают не исходник, а манифест
проекта (little-endian):

```text
magic "LPF1" (4 bytes)
u32 file_count
file_count × { u32 path_len, path utf8, u32 src_len, src utf8 }
u32 entry_index
```

Пути относительные (`main.lat`, `lib/math.lat`), entry задаётся индексом в
списке. Ответ — тот же `[status][len][payload]`. Однофайловый `latent_compile`
импорты не поддерживает и на них возвращает ошибку с подсказкой про
`compile_files`; детали и ограничения — в
[модулях](../guide/modules.md) и [CLI](./cli.md#многофайловый-abi-latent_compile_files).

## Ограничения и дефекты

- Лимита памяти нет, но `memory.grow` при неудаче не диагностируется.
- Данные-секции — по сегменту на строку; при большом числе литералов модуль
  растёт быстро.
- Нет таблицы, если нет лямбд; нет start-секции; `env.print` инстанцируется
  всегда.
- Enum-таблица глобальна по именам вариантов.
- Float в массивах/полях/лямбдах не имеет полноценного представления —
  появляются невалидные модули (см.
  [дефекты](./errors.md#известные-ограничения-движка-2-компилируется-но-невалидный-wasm)).
