# Система типов

Источник истины: `src/typechecker/` (движок №2), `src/ast/expr.rs` (`Type`),
`src/codegen/context.rs` (`latent_to_wasm`, `StaticTy`). Движок №1 **не имеет**
тайпчекера: аннотации типов он разбирает и отбрасывает, ошибки типов проявляются
только в рантайме как JS-исключения.

## Базовые типы

| Тип | В WASM (движок №2) | Литерал/значение | Примечание |
|---|---|---|---|
| `int` | `i32` | `42` | целое 32 бита со знаком |
| `float` | `f64` | `3.14` | двойная точность |
| `bool` | `i32` (0/1) | `true`, `false` | результат сравнений и логики |
| `string` | `i32` (указатель) | `"abc"` | `[len u32 LE][utf8]`, `len` в байтах |
| `null` | `i32` (0) | `null` | нулевой указатель |
| `unit` / `void` | `i32` в сигнатуре, но значения нет | — | см. ниже |
| `[T]` | `i32` (указатель) | `[1, 2, 3]` | `[len u32][элементы по 4 байта]` |
| `fn(T, ...) -> R` | `i32` (указатель на замыкание) | `fn(x) => x` | `[table_slot][env_ptr]` |
| `Name` | `i32` / layout класса | `new Point(...)` | именованный тип класса/enum |
| `Name<A, B>` | зависит | `Model<string>` | generic-аннотация; в WASM обычно `i32` |

`unit` и `void` — синонимы в системе типов: оба отображаются в `Type::Unit`
(`src/typechecker/infer/stmt.rs`, `parse_type_annotation`). В сигнатуре функции с
`-> unit`/`-> void` кодоген всё равно ставит результат `i32` и дописывает
`i32.const 0`, если тело не завершается `return` (`src/codegen/compile_fn.rs`).

```latent
fn log(msg: string) -> unit {
    print(msg);
}

fn main() -> int {
    log("hello");
    return 0;
}
```

## Внутреннее представление типов

```text
Type ::= Int | Float | Bool | String | Null | Unit
       | Var($Tn) | Named(имя)
       | Array(Type) | Fn([Type], Type)
       | Tuple([Type])           (* в v0.1 не создаётся парсером *)
       | Generic(имя, [Type])
       | Poly(vars, Type)        (* результат обобщения *)
```

- `Poly` — схема полиморфизма, создаётся `generalize`, снимается
  `instantiate` при каждом обращении к имени.
- Отдельных AI- и concurrency-типов (`AIType`, `ConcurrencyType` из
  `src/types.rs`) тайпчекер **не использует**: это задел «Части I», а рабочая
  модель — общий `Type`.
- `LatentType`/`AIType`/`ConcurrencyType` (`src/types.rs`) — тоже реликтовые
  типы для документации/тестов; компилятор работает с `typechecker::Type`.

## Вывод типов

Typechecker реализует вариант Hindley–Milner: подстановки, унификация,
occurs-check, обобщение/инстанцирование.

1. **Хойстинг функций.** Сначала в окружение попадают сигнатуры всех функций
   программы (параметры без аннотаций — свежие типовые переменные; возврат без
   аннотации — `unit`; у `async fn` возврат оборачивается в
   `Generic("Promise", [T])`). Поэтому вызовы работают до объявления:
   ```latent
   fn main() -> int {
       return later();
   }

   fn later() -> int {
       return 7;
   }
   ```
2. **Хойстинг вариантов enum** и встроенных `Ok`/`Err`/`Some`/`None`: 0-арный
   вариант получает тип `Named(Enum)`, вариант с полями — тип
   `Fn([поля], Named(Enum))`. Имя enum тоже связывается как `Named(Enum)`.
3. **Обход инструкций.** Для каждой инструкции выводятся типы, ошибки
   накапливаются (проверяется вся программа, а не только первая ошибка).
4. **Обобщение** (`generalize`) делается для `let` и при повторном
   связывании функции после вывода тела; при использовании имени `Poly`
   инстанцируется свежими переменными. Но у `fn` генерализация фактически
   ломается: при обобщении сигнатура функции уже лежит в окружении со своими
   свободными переменными, поэтому `gen_vars` пуст и функция остаётся
   мономорфной до первого вызова. Для `let`-лямбд полиморфизм работает:
   ```latent
   fn main() -> int {
       let id = fn(x) => x;
       let a = id(1);      // $T = float
       let b = id("str");  // свежая переменная — работает
       return a;
   }
   ```
   А `fn id(x) { return x; }` с вызовами `id(1)` и `id("str")` даёт ошибку
   типов («Несовпадение типов …: ожидалось 'string', найдено 'float'»), потому
   что первый вызов зафиксировал тип параметра.

### Как типизируются выражения (выжимка из `infer/expr.rs`)

| Выражение | Тип результата |
|---|---|
| `42`, `3.14` | **`Float`** — оба литерала (важно: не `Int`) |
| `"..."`, `true`, `null` | `String`, `Bool`, `Null` |
| `a + b` | `String`, если хотя бы одна сторона `String`; иначе `Float` |
| `a - b`, `a * b`, `a / b`, `a % b` | `Float` |
| `a == b`, `a != b`, сравнения, `&&`, `\|\|` | `Bool` |
| `a & b`, `a \| b`, `a ^ b`, `a << b`, `a >> b` | `Int` |
| `-a` | `Float`; `!a` → `Bool` |
| `arr[i]` | тип элемента массива; для `String` — `Int` (байт) |
| `[1, "a"]` | `Array(fresh)` — гомогенность **не** требуется |
| `fn(x) => expr` | `Fn(fresh..., fresh)` |
| `f(args)` | тип возврата `f`; аргументы унифицируются с параметрами |
| `await x` | `T`, если `x : Promise<T>`, иначе ошибка |
| `match x { ... }` | тип тел всех веток (унифицируются между собой) |
| `new Class(...)` | `Named(Class)` |
| `obj.field` | «свежая переменная», кроме особого случая `Point.x/.y` → `Float` |

Присваивание (`=`): типы цели и значения унифицируются; у присваивания тип
цели. Исключение — присваивание в элемент массива (`a[i] = v`): тип не
проверяется, результатом считается тип значения (массивы в Latent «как
словари»).

### Что typechecker проверяет

- использование необъявленного имени (переменной или функции) —
  «Неопределённая переменная 'x'»;
- арность вызова известной функции — «Несовпадение арности…»;
- тип условия `if`/`while` — должен унифицироваться с `bool`;
- тип итерабельного в `for (let x in arr)` — должен быть массивом;
  (строки недопустимы: `for (x in "ab")` — ошибка типов);
- аннотацию `let` против значения;
- аннотацию возврата функции против типа последнего `return`;
- совместимость аргументов с параметрами (через унификацию `Fn`);
- `await` применяется только к `Promise<T>`;
- единственное совпадение имён пользовательских типов: `Named(a)` унифицируется
  с `Named(b)` только при `a == b`;
- бесконечные типы (occurs-check), например для `let f = fn(x) => f(x);`.

### Что typechecker игнорирует

Это критично для чтения кода — компиляция не гарантирует «типовую
корректность»:

- **операнды арифметики не проверяются**: `a - b`, `a * b`, `a / b`, `a % b`
  всегда дают `Float`, чем бы ни были `a` и `b`; `+` проверяет только наличие
  `String` для конкатенации;
- **операнды сравнений не проверяются**: `1 < 2 < 3`, `"a" < 1` типизируются
  без ошибок;
- **унарные `-`/`!`** принимают любой операнд;
- **индекс** требует лишь «числовой» индекс (унификация с `Float`), тип объекта
  не ограничивается массивом;
- **поля объектов**: строгой типизации записей нет; `obj.field` — «свежая
  переменная», кроме остаточного спецслучая `Generic("Point")` с полями
  `x`/`y` типа `Float`. Для остальных классов поле не проверяется;
- **методы**: кроме каналов, вызов метода возвращает свежую переменную,
  аргументы проверяются, но сигнатура метода не ищется;
- **`null` не образует nullable-типов**: `null` унифицируется только с `null`;
  `let x: int = null` — ошибка, но `x == null` компилируется (сравнение типы
  не проверяет);
- **`MissingReturn` не порождается**: функция с аннотацией возврата и без
  `return` может пройти проверку (и затем получить `i32.const 0` в кодогене);
- **`Tuple`** и **`Union`** не создаются парсером — код проверки на них есть,
  но он недостижим;
- AI-типы (`AiLoad`, `AiInfer`, …) типизируются упрощённо, а парсер их не
  создаёт (кроме `ai_generate!`).

## Ловушки кодогена, связанные с типами

Тайпчекер и кодоген используют **разные** модели типов. Кодоген опирается на
best-effort `StaticTy` (`Int`, `Float`, `Bool`, `Str`, `Array`, `Fn`,
`Unknown`), выводимый из аннотаций, литералов и локальных переменных. Отсюда
наблюдаемые особенности (проверены на `web-ide/compiler.wasm`):

- числовой литерал — `Float` для тайпчекера, но `Int` для кодогена, если дробная
  часть нулевая. Поэтому `let x: float = 2;` и `fn f() -> float { return 5.0; }`
  компилируются, но **WASM невалиден** (`i32.const` в f64-локаль/результат);
- `fn f() -> float { return 2.5; }` и `let x: float = 2.5;` — валидны;
- правило: `float` работает, только если **и слот, и все операнды** синтаксически
  «дробные» (ненулевая дробная часть). `2.0`, `5.0`, `1e3` — ломают f64-контекст;
- смешанная арифметика `1 + 2.5` даёт невалидный WASM (левый операнд `i32`),
  хотя типы унифицируются (`int`↔`float` считаются совместимыми);
- float-параметры (`fn f(x: float)`) валидны, если аргумент — float-выражение;
  вызов `f(1)` даст невалидный WASM;
- массивы с float (`[1.5, 2.5]`), `a[i] = 1.5`, захват float лямбдой, `match`
  с void-ветками, `fn f() -> unit { return; }`, `let x = print("a");` — всё это
  компилируется, но даёт невалидный WASM (полный список —
  [errors → известные ограничения](./errors.md#известные-ограничения-движка-2-компилируется-но-невалидный-wasm));
- поле класса `float` имеет размер 8 байт (`f64`), остальные поля — 4 (`i32`);
  float-поля/float-параметры классов в методах дают невалидный модуль;
- `bool` в кодогене — это `i32`, поэтому `print(true)` печатает `1`, а не
  `true` (в движке №1 — `true`);
- результат строковой операции (`str`, `.to_str()`) кодоген иногда считает
  `Int` и печатает число-указатель; это следствие `StaticTy`, а не тайпчекера.

## Области видимости

- Каждый блок `{ ... }` (тело функции, ветки `if`, тело цикла, лямбда) создаёт
  новую область; выход удаляет её.
- Функции и enum-варианты хойстятся на уровень программы.
- `let` в одной области может перекрыть имя из внешней; ошибки повторного
  объявления нет.
- Классы регистрируются в окружении как `Generic(Имя, [])`; внутри методов
  связывается `this` этого типа.
- Лямбда получает новую область с параметрами; свободные переменные
  захватываются по значению (в кодогене — через env).
