# Лексика

Источник истины: `src/lexer/` (движок №2) и `web-ide/compiler/lexer.js` (движок
№1). Лексер превращает UTF-8 исходник в поток токенов с позицией `L:C`
(`src/lexer/position.rs`, нумерация с 1, `column` считается в символах, `offset`
— в байтах).

## Пробелы и переводы строк

Пропускаются символы `' '`, `'\t'`, `'\n'`, `'\r'` (`skip_whitespace` в
`src/lexer/scanner.rs`). Пробелы не значимы, кроме разделения токенов; отступы
влияют только на форматирование.

## Комментарии

| Вид | Синтаксис | Движок №2 | Движок №1 |
|---|---|---|---|
| строчный | `// до конца строки` | ✅ | ✅ |
| блочный | `/* ... */`, **с вложенностью** | ✅ | ❌ не поддерживается |
| блочный незакрытый | `/* ...` до EOF | ошибка «Незавершённый блочный комментарий» | — |

Токены комментариев в движке №2 формируются лексером (`TokenType::Comment`), но
**удаляются до парсинга** (`src/parser/mod.rs`): комментарии можно ставить в
любом месте между токенами, включая начало файла.

```latent
// Строчный комментарий
fn main() -> int {
    /* Блочный комментарий.
       /* Вложенный комментарий — допустим. */
       Продолжение. */
    return 1;
}
```

В движке №1 лексер понимает только `//`; символы `/*` он разберёт как оператор
деления и `*`, что приведёт к ошибке парсинга.

## Числовые литералы

Один вид — десятичные числа; всё хранится как `f64` (`TokenType::Number(f64)`),
а кодогенератор выбирает `i32.const` или `f64.const` по тому, есть ли дробная
часть (`src/codegen/emit_expr.rs`).

```
Number   ::= Digit+ ('.' Digit+)? ([eE] ('+'|'-')? Digit+)?
Digit    ::= [0-9]
```

- `42`, `3.14`, `1e10`, `1.5e-3` — корректно.
- `1.` (точка без цифр после) — это число `1` и затем отдельный токен `.`
  (точка).
- `1e`, `1e+` — ошибка «Неверный формат числа '...'».
- Шестнадцатеричных (`0x`), двоичных (`0b`), восьмеричных литералов и
  разделителей `_` **нет**.
- `2.0` — лексически число с плавающей точкой, но кодогенератор всё равно
  эмитит его как `i32.const 2`, если дробная часть нулевая. Это источник
  известных проблем с float (см. [типы](./types.md#ловушки-кодогена-связанные-с-типами)).

Движок №1 не поддерживает экспоненту: `1e3` разберётся как число `1` и
идентификатор `e3`.

## Строковые литералы

Только двойные кавычки, одна строка (перевод строки внутри литерала
запрещён). Допустимые escape-последовательности — **ровно четыре**:

| escape | результат |
|---|---|
| `\n` | перевод строки |
| `\t` | табуляция |
| `\\` | обратный слэш |
| `\"` | двойная кавычка |

Любой другой `\X` — ошибка «Неверная escape-последовательность '\X'». Строка
без закрывающей кавычки до перевода строки или до EOF — «Незавершённая строка».

```latent
fn main() -> int {
    print("tab:\tquote:\"slash:\\");
    return 0;
}
```

Строка хранится в памяти как `[len u32 LE][utf8 bytes]`, указатель — на длину
(см. [WASM ABI](./wasm-abi.md#строка)). Индексация `s[i]` даёт **байт** UTF-8,
а не символ; `len(s)` — длину в байтах.

## Идентификаторы

```
Identifier ::= (Letter | '_') (Letter | Digit | '_')*
Letter     ::= [A-Za-z]      // только ASCII
```

Валидность проверяется также функцией `latent::is_valid_identifier`
(`src/lib.rs`): первая буква — ASCII-алфавитная или `_`, остальные — ASCII
буквы/цифры/`_`. Кириллические имена **не** являются идентификаторами.

## Ключевые слова и «мягкие» ключевые слова

Полный список ключевых слов (`src/lexer/keywords.rs`): `let fn if else while
for in return class new this async await spawn channel select case default yield
match enum true false null ai model agent embedding tensor semantic test assert
assert_eq forall snapshot ai_contract enforce_contract`.

Часть слов — **мягкие**: лексер помечает их отдельным типом токена, но в
позиции имени они принимаются как идентификаторы (`soft_keyword_lexeme()` в
`src/lexer/token.rs`, `expect_identifier` в `src/parser/cursor.rs`):

`test`, `assert`, `assert_eq`, `forall`, `snapshot`, `ai_contract`,
`enforce_contract`, `model`, `agent`, `embedding`, `tensor`, `semantic`,
`case`.

Это значит, что легальны, например, `let test = 5;`, `fn model() {}`,
`obj.agent`:

```latent
fn model() -> int { return 1; }

fn main() -> int {
    let test = 5;
    let case = 2;
    return model() + test + case;
}
```

Твёрдые ключевые слова (`let`, `fn`, `if`, `class`, `match`, `true`, `ai`, …) в
позиции имени **не** принимаются. Например, `let if = 1;` — ошибка парсинга
«ожидалось 'identifier', найдено If».

В движке №1 наборы другие: `web-ide/compiler/token.js` содержит `KEYWORDS`
(включая `print`) и `SOFT_KEYWORDS`; слов `model`, `agent`, `embedding` там нет
вовсе — они лексируются как обычные идентификаторы. Слово `default` в движке №1
— твёрдое ключевое слово, а в движке №2 — твёрдое (не мягкое).

## Операторные символы

Лексер распознаёт: `+ - * / %` ; `= == != < <= > >=` ; `&& || !` ;
`& | ^ << >>` ; `-> => <-` ; пунктуацию `( ) { } [ ] ; , . : :: @`.

- `::` распознаётся как отдельный токен, но **нигде не используется**
  парсером (зарезервировано).
- Составных присваиваний (`+=`, `-=`, `*=`, `/=`, `%=`) **нет**: `x /= 2`
  разберётся как `x`, `/`, `=`, `2` и даст ошибку парсинга.
- Символы, не входящие в набор (например `#`, `$`, `?`, `~`), дают ошибку
  «Неожиданный символ '# ' на строке L:C».

## Точка с запятой

Движок №2 требует `;` после:

- объявления `let`;
- `return` (в том числе `return;`);
- выражения-инструкции (`foo();`);
- `yield;`;
- поля класса (`x: int;`);
- `match` в позиции инструкции (`match x { ... };`).

Не требуют `;`: `if`, `while`, `for`, `spawn`, `class`, `enum`, `fn`, `test`,
`@decorator`, `select` (точка с запятой после `select` допустима и
съедается).

```latent
fn main() -> int {
    let x = 1;                  // ; обязательна
    if (x == 1) { print("ok"); } // ; не нужна
    return x;
}
```

Движок №1 гораздо терпимее: `;` там опционален почти везде (`match(TokenType.Punct, ';')`
вместо `expect`), поэтому код без `;` в IDE может работать, а движком №2 не
скомпилируется.

## Кодировка и BOM

Исходник — UTF-8 **без BOM**. Символ BOM (`U+FEFF`) лексер не пропускает:
- движок №2 (wasm) выдаёт `Неожиданный символ '﻿' на строке 1:4294967295`
  (столбец вычисляется с переполнением — дефект);
- нативная debug-сборка `latentc` падает с panic
  `attempt to subtract with overflow` в `src/lexer/next_token.rs`.

Сохраняйте файлы без BOM (в VS Code: `files.encoding: utf8`, без «UTF-8 with
BOM»; в PowerShell 7 `Set-Content -Encoding utf8NoBOM`).

## Позиции в диагностиках

Позиция токена — `Position { line, column, offset }`; в текстах ошибок
печатается как `на строке L:C`. Точка отсчёта — 1:1. Для ошибок лексера
позиция указывает на начало проблемного токена (для `\X` — на символ после
слэша).
