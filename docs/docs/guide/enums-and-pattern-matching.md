# Enum и pattern matching

## Объявление

```text
enum Имя { Вариант, Вариант(Тип, ...), ... }
```

- запятая между вариантами **обязательна** (`enum E { A B }` — ошибка),
  завершающая допускается;
- тег — порядковый номер варианта: `enum Color { Red, Green, Blue }` →
  `Red=0`, `Green=1`, `Blue=2`;
- вариант без полей — **число-тег** (`i32`);
- вариант с полями — указатель на блок `[тег][поле0][поле1]...`; поля по 4 байта.

```latent
enum Shape { Circle(int), Rect(int, int), Empty }

fn area(s: Shape) -> int {
    return match s {
        // 0-арный вариант должен идти раньше вариантов с полями:
        // для него проверяется значение-тег, а не тег по указателю.
        case Empty(): 0,
        case Circle(r): 3 * r * r,
        case Rect(w, h): w * h,
    };
}

fn main() -> int {
    print("circle:", area(Circle(10)));
    print("rect:", area(Rect(3, 4)));
    return area(Circle(10));
}
```

## Конструирование

```latent
enum Color { Red, Green, Blue }

fn code(c: Color) -> int {
    return match c {
        case Red(): 0,
        case Green(): 1,
        case Blue(): 2,
    };
}

fn main() -> int {
    print("red:", code(Red));
    print("green:", code(Green));
    return code(Blue);
}
```

- `Circle(10)` — вызов конструктора варианта;
- `Red` — значение-тег (без скобок);
- `Red()` в **выражении** — ошибка типов: 0-арный вариант зарегистрирован как
  значение, а не функция. В **паттерне** `case Red():` — корректный
  конструктор с нулём полей.

## `match`

`match` — выражение:

```text
match scrutinee {
    case Паттерн: выражение,
    ...
    default: выражение,
}
```

```latent
fn classify(n: int) -> string {
    return match n {
        case 0: "zero",
        case 1: "one",
        default: "many",
    };
}

fn main() -> int {
    print(classify(0));
    print(classify(5));
    return 0;
}
```

Правила паттернов:

| Паттерн | Пример | Поведение |
|---|---|---|
| литерал-число | `case 0:` | сравнение значения |
| литерал-строка | `case "a":` | сравнение через `str_eq` |
| wildcard | `case _:` / `default:` | всегда, обычно последний |
| идентификатор | `case x:` | **связывает** значение, срабатывает всегда |
| конструктор | `case Circle(r):` | проверяет тег, связывает поля |
| конструктор 0-арный | `case Empty():` | сравнивает тег (нужны скобки!) |

Ограничения синтаксиса:

- ветки разделяются запятыми; последняя запятая необязательна;
- тело ветки — **выражение**, не блок: `case 1: { 5 }` — ошибка;
- `case` можно опустить: `match n { 1: "one", default: "many" }`;
- bool-литералы в паттернах не поддерживаются: `case true:` — ошибка
  `ожидалось 'pattern', найдено Bool(true)`;
- `match` с void-ветками (`print(...)` в ветке) даёт невалидный WASM —
  ветка обязана возвращать значение, либо используйте `match` как инструкцию
  с `;` и единым типом веток;
- `match` без `;` как инструкция — ошибка парсинга.

## `Ok`/`Err` без объявления

```latent
fn from_result(r) -> int {
    return match r {
        case Ok(v): v,
        case Err(e): -1,
    };
}

fn main() -> int {
    print(from_result(Ok(42)));
    print(from_result(Err("bad")));
    return from_result(Ok(7));
}
```

Встроенные варианты: `Ok` (тег 0, 1 поле), `Err` (тег 1, 1 поле),
`Some` (тег 0, 1 поле), `None` (тег 0, 0 полей).

:::caution Some/None

`Some` и `None` имеют один тег `0`, а `Some`-значение — указатель. Из-за этого
паттерны `Some`/`None` в движке №2 семантически ненадёжны. Используйте
`Ok`/`Err`.

:::

## Как match компилируется

Цепочка вложенных `if/else`:

1. scrutinee вычисляется один раз и сохраняется в локальную;
2. для литерала — сравнение (`i32.eq`/`f64.eq`/`str_eq`);
3. для конструктора — загрузка тега и сравнение (или сравнение значения для
   0-арного варианта);
4. поля связываются в THEN-ветке;
5. wildcard/`default` — безусловное исполнение.

Если ни одна ветка не совпала и нет `default`, результат — `0`.

## Ограничения движка №2

- `enum` не поддерживается JS-интерпретатором (движок №1): `Unexpected token
  '{'`. Это фича движка №2.
- Паттерны-bool не поддерживаются парсером.
- Void-ветки дают невалидный WASM.
- Вложенные конструкторы в паттернах не проверяются: связываются только
  поля верхнего уровня.
- Дубликаты вариантов/enum не диагностируются.
- Float-поля enum невалидны (поля хранятся по 4 байта).
- Паттерн-конструктор на время проверки ветки перекрывает имя варианта как
  функцию; не используйте вариант как значение в последующих ветках того же
  `match` — это может дать ложную ошибку типов.
- 0-арные варианты должны стоять в `match` **раньше** вариантов с полями:
  для них проверяется значение-тег, а для вариантов с полями тег читается по
  указателю. Иначе значение-тег может быть ложно прочитано как указатель.
- Кодоген не проверяет исчерпывающесть: без `default` результат — `0`.
