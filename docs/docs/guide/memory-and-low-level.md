# Память и низкий уровень

## Модель памяти

Движок №2 компилирует Latent в WASM-модуль с **собственной линейной памятью**:

- страницы по 64 КиБ, начальный размер — **16 страниц** (1 МиБ), `max` не
  задан; память растёт через `memory.grow` в аллокаторе;
- ниже адреса `1024` — служебная область, строковые константы из data-секции;
- выше — куча: **bump-аллокатор**. Единственная операция — «сдвинуть указатель
  кучи вперёд»; освобождения памяти (`free`) и сборки мусора **нет**;
- границы блоков не проверяются.

Следствия: долгоживущие программы постоянно растут; выход за границы массива
или строки — порча памяти или trap; `push` в массив пишет за конец выделенного
блока (см. оговорку в [массивах](./arrays-and-strings.md)).

## Раскладка значений

| Значение | Формат в памяти |
|---|---|
| строка | `[len u32 LE][байты UTF-8]`; указатель — на `len` |
| массив | `[len u32][элемент0][элемент1]...`; элементы по 4 байта |
| класс | поля по смещениям с выравниванием 4 (все по 4 байта, `float` — 8) |
| enum-вариант с полями | `[tag i32][поле0][поле1]...` |
| 0-арный enum-вариант | число-тег (`i32`), не указатель |
| `bool` | `i32` `0`/`1` |
| `null` | `0` |
| замыкание | 8 байт: `[индекс функции в таблице][env-указатель]` |

Посмотреть на раскладку можно через `len`/индексацию:

```latent
fn main() -> int {
    let data = [10, 20, 30];
    print("array length:", len(data));
    print("element[2]:", data[2]);

    let text = "abc";
    print("string bytes:", len(text));
    print("byte[0]:", text[0]); // 97 — код 'a'
    return 0;
}
```

## Примитивы линейной памяти

В компиляторе (движок №2, `src/`) есть шесть builtin'ов для селф-хостинга, и они
**есть в поставляемом `web-ide/compiler.wasm`** — пример ниже компилируется и
исполняется:

| Функция | Арность | Смысл |
|---|---|---|
| `alloc(size) -> int` | 1 | выделить `size` байт, вернуть указатель (bump + grow) |
| `load8(addr) -> int` | 1 | беззнаковый байт по адресу |
| `store8(addr, value)` | 2 | записать младший байт |
| `load32(addr) -> int` | 1 | 32-битное слово (little-endian) |
| `store32(addr, value)` | 2 | записать 32-битное слово |
| `memcopy(dst, src, len)` | 3 | побайтовое копирование |

```latent
fn main() -> int {
    let p = alloc(8);
    store8(p, 65);          // p[0] = 65 ('A')
    store32(p + 4, 12345);  // p[4..8] = 12345, little-endian
    print(load8(p));        // 65
    print(load32(p + 4));   // 12345
    memcopy(p + 16, p, 8);  // копия 8 байт
    print(load8(p + 16));   // 65
    return 0;
}
```

Программа печатает `65`, `12345`, `65` (по строке на аргумент `print`).

:::note
Исходники builtin'ов — `src/codegen/emit_call/direct.rs`
(`compile_memory_builtin`), регистрация вызовов — `emit_call/mod.rs`.
Если вы работаете со **старой** сборкой `compiler.wasm`, `alloc` даст
«Неопределённая переменная 'alloc'»; актуальная сборка (651 473 байт, собрана
из текущего `src/`) их поддерживает. Пересборка — в
[bootstrap](../tooling/bootstrap.md#2-compilerwasm-для-web-ide-движок-2).
:::

## Зачем это нужно

- **Self-hosting**: компилятор на самом Latent (`selfhost/`) пишет байты WASM
  через `store8`/`store32` и копирует буферы через `memcopy`.
- **Ручные структуры данных**: при желании можно реализовать свой аллокатор,
  связные списки, строки фиксированной длины и т.п.
- **Отладка раскладки**: понимание форматов помогает читать дампы памяти и
  ABI.

## Ограничения движка №2

- Нет `free`/GC: вся выделенная память остаётся занятой.
- Нет проверки границ: `arr[i]` и `load8(addr)` не валидируются.
- `push` расширяет массив за пределы выделенного блока (bump-аллокатор без
  отдельной ёмкости) — см. предупреждение в
  [массивах](./arrays-and-strings.md).
- `pop()` на пустом массиве читает `arr[-1]`.
- Массивы `float` невалидны (элементы пишутся `i32.store`).
- Memory-builtins есть в актуальной сборке `compiler.wasm`; если вы взяли
  старый артефакт (например, встроенный в IDEA-плагин) — пересоберите или
  укажите актуальный путь.
- `f64_to_str` ограничен диапазоном `i32` для целой части; экстремальные float
  могут дать trap.
