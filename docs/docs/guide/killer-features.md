# Что Latent даёт фронтенду

Latent не заменяет React, Vue или TypeScript. Его ниша — вычислительное
WASM-ядро рядом с UI: данные, canvas/аудио/физика, парсинг, AI. Сервер для этого
не нужен: конкурентность и AI записаны в грамматике, компилятор умеет
компилировать сам себя, а память детерминирована.

Ниже — семь вещей, которые стоит попробовать, и то, где они заканчиваются. Блоки
`// host-only` исполняет движок №1; остальные проверяет компилятор №2.

:::note О чём этот раздел

Latent — не «JS, но лучше» и не замена фреймворкам. Это язык для ядра:
маленький WASM-модуль с одним импортом `env.print`, где CSP, AI и self-host
встроены в синтаксис; UI, DOM, сеть и состояние остаются на JS/TS.

:::

## 1. CSP-конкурентность в языке

**Как это устроено.** `spawn`, `channel()`, `select`, `yield`, `ch <- v` и `<-ch` — ключевые слова и
синтаксис, а не импорт из пакета. Движок №1 исполняет их на кооперативном планировщике:
`send` кладёт значение в очередь, `recv` уступает планировщику, пока очередь пуста, `select`
ждёт первый готовый канал, `yield` добровольно отдаёт управление.

```latent
// host-only: каналы и планировщик — движок №1; движок №2 отвергает channel.
fn worker(jobs: channel, results: channel, count: int) {
    for (let i = 0; i < count; i = i + 1) {
        let job = jobs.recv();
        results <- job * job;
    }
}

fn main() -> int {
    let jobs = channel();
    let results = channel();
    for (let w = 0; w < 4; w = w + 1) { spawn worker(jobs, results, 4); }
    for (let j = 1; j <= 16; j = j + 1) { jobs <- j; }
    let total = 0;
    for (let k = 0; k < 16; k = k + 1) { total = total + <-results; }
    return total;
}
```

**Что это даёт.** Worker pool, fan-out/fan-in и `select` — десяток строк без зависимостей. В
JS каналов нет: нужна библиотека или самодельная очередь на Promise с `AbortController`, а
`Promise.race` не умеет «ждать первый готовый канал» так же естественно.

**Где предел.** Это конкурентность, а не параллелизм: один поток, нет вытеснения, долгий цикл
без `yield`/`recv` блокирует остальные горутины. Нет отмены, таймаутов и приоритетов; для
реального параллелизма в JS есть Web Workers, а каналы исполняет только движок №1 — это
host-фича, не WASM-код.

**Попробовать.** <a href="/latent/demos/concurrency/">/latent/demos/concurrency/</a> —
планировщик, 1 000 горутин, worker pool, `select`-гонка. Теория:
[Конкурентность](./concurrency.md), [разбор примеров](../examples/concurrency.md).

## 2. AI-примитивы как синтаксис

**Как это устроено.** `ai_infer`, `ai_embed`, `ai_stream`/`stream_next`, `tensor`, `semantic`,
`matmul`, `cosine_similarity`, `ai_generate!` — встроенные функции и ключевые слова. Их
видит парсер, а значит — IDE, MCP-сервер и линтер: это не SDK, который надо устанавливать. В
браузере их исполняет движок №1: с провайдером — гейтвей, без него — детерминированный mock
(эмбеддинг из 8 измерений).

```latent
// host-only: AI-примитивы исполняет движок №1 (mock или гейтвей).
fn main() -> int {
    print(ai_infer("gpt-4", "Explain CSP in one sentence"));
    let query = ai_embed("CSP concurrency in a language");
    let docs = ["goroutines and channels", "promise chains in JavaScript"];
    for (let i = 0; i < docs.length; i = i + 1) {
        print("similarity:", cosine_similarity(query, ai_embed(docs[i])));
    }
    return 0;
}
```

**Что это даёт.** В JS AI-вызов — это `fetch` + JSON + ручной разбор: типы теряются,
стриминг пишется руками, инструменты не видят ничего, кроме строки. В Latent
`ai_stream`/`stream_next` — часть языка, а `ai_embed` возвращает вектор для
`cosine_similarity`/`matmul`. Mock детерминирован, поэтому демо и тесты работают офлайн, без
ключей и CORS.

**Где предел.** Вызов всё равно уходит на хост: движок №2 отвергает примитивы ошибкой «требует
host-рантайма». Нет типизированных ответов, схем, ретраев и учёта токенов; стриминг —
итератор без backpressure; ключи и CORS — забота хоста. В продакшене вызов почти всегда
делает JS или бекенд.

**Попробовать.** <a href="/latent/demos/ai/">/latent/demos/ai/</a> — prompt → embedding →
heatmap → infer → стриминг, офлайн mock. Теория: [AI-примитивы](./ai-features.md),
[AI-кейсы](../examples/ai.md).

## 3. Self-hosted компилятор в браузере

**Как это устроено.** Компилятор Latent написан на самом Latent (`selfhost/shc.lat`) и собран в WASM.
`selfhost/seed.wasm` (≈41 КБ) — работающий self-hosted компилятор, которому не нужны ни
Rust, ни `cargo`, ни сервер. Цепочка bootstrap доходит до **фиксированной точки**: третий
stage побайтово совпадает со вторым.

```text
seed.wasm --(shc.lat)--> stage1' --(shc.lat)--> stage2' --(shc.lat)--> stage3'
stage2' === stage3'                         FIXED POINT (побайтово)
```

Поэтому в браузере можно взять `seed.wasm`, скормить ему исходник и получить валидный
WASM-модуль — без запроса к серверу компиляции:

```latent
fn main() -> int {
    print("compiled in the browser");
    return 0;
}
```

**Что это даёт.** Компилятор как ассет, а не сервис: нет бэкенда, очереди и утечки
исходников, работает офлайн. Для playground это полный тулчейн в `.wasm` на десятки
килобайт.

**Где предел.** Seed — снимок компилятора: чтобы добавить новую конструкцию, один раз всё
равно нужен Rust (`--update-seed`). Компилируется подмножество (без host-фич), нет source
maps и оптимизаций, а кэш — только по исходнику.

**Попробовать.** <a href="/latent/demos/selfhost/">/latent/demos/selfhost/</a> — загрузка
seed, компиляция, хэши, fixed point. Теория: [спецификация self-host](../specs/selfhost.md),
[WASM и исполнение](./wasm-and-execution.md).

## 4. WASM-песочница по построению

**Как это устроено.** Скомпилированный модуль экспортирует `memory` и `main`, а импортирует **ровно
одну** функцию — `env.print(i32)`. У него нет доступа к DOM, `fetch`, `localStorage`,
таймерам и случайным числам: этих импортов не существует, а не «запрещены политикой». Всё,
что модуль может сделать с миром, — попросить хост напечатать строку из памяти.

```js
// Хост даёт модулю только print — и ничего больше.
const imports = {env: {print: (ptr) => readAndLog(instance, ptr)}};
const {instance} = await WebAssembly.instantiate(bytes, imports);
instance.exports.main();
```

```latent
fn main() -> int {
    let buf = alloc(16);
    store32(buf, 42);
    print("stored:", load32(buf));
    return 0;
}
```

**Что это даёт.** `eval` и `new Function` исполняют код с полными правами страницы: DOM,
куки, сеть, прототипы. Модуль Latent по построению не имеет ambient authority: чтобы что-то
разрешить, хост должен явно передать импорт. Для сгенерированного AI-кода и плагинов это
качественно другая модель.

**Где предел.** Песочница не ограничивает CPU и память сама: бесконечный цикл надо убивать
через Worker + `terminate`, а `memory.grow` — лимитировать на хосте (fuel/таймаутов в модуле
нет). Нет capability-API, кроме `print`; границы массивов не проверяются.

**Попробовать.** <a href="/latent/demos/sandbox/">/latent/demos/sandbox/</a> — редактор →
`compiler.wasm` → Web Worker, «атаки», capability-список и лог изоляции. Теория: [Latent во
фронтенде](./web-and-frontend.md), [WASM ABI](../reference/wasm-abi.md).

## 5. Детерминированная память без GC

**Как это устроено.** У модуля своя линейная память: 16 страниц по 64 КиБ на старте, рост через
`memory.grow`. Аллокатор — **bump**: единственная операция — сдвинуть указатель кучи вперёд.
Сборки мусора и `free` нет, поэтому нет и непредсказуемых пауз.

```latent
// Bump-аллокатор: выделение только вперёд, освобождения нет.
fn main() -> int {
    let frame = alloc(64);
    let i = 0;
    while (i < 16) {
        store32(frame + i * 4, i * i);
        i = i + 1;
    }
    print("frame[15]:", load32(frame + 60));
    return 0;
}
```

Для анимации это удобно: буфер кадра выделяется один раз и перезаписывается, а не создаётся
заново каждый `requestAnimationFrame`. Демо физики показывает frame-time: у JS — спайки GC,
у Latent-ядра — плоская линия.

**Что это даёт.** Нет GC-пауз и роста p99; память предсказуема и разложена вручную; рантайм
крошечный. Для аудио (нельзя пропустить буфер), canvas и физики стабильный кадр важнее
средней скорости.

**Где предел.** Память только растёт: долгоживущая страница должна пересоздавать экземпляр или
переиспользовать буферы. `push` не резервирует ёмкость и может писать за выделенный блок;
`free` и арен нет — для долгого CRUD GC удобнее.

**Попробовать.** <a href="/latent/demos/physics/">/latent/demos/physics/</a> ·
<a href="/latent/demos/">/latent/demos/</a> · [Память](./memory-and-low-level.md).

## 6. Модули и ленивые чанки

**Как это устроено.** Две связанные вещи. **Ленивые чанки** уже работают в playground: WASM — ассет,
а не точка входа, поэтому загрузчик прячется за `dynamic import()`, а `manualChunks` делит
бандл на `engine2`, `ai`, `editor`, `examples` и `core`. **Модули** — файловые
`import`/`export` с линковкой на этапе компиляции — реализованы в v1: `export` перед
top-level `fn`/`class`/`enum`, именованный импорт с алиасом, двухфазная линковка с
манглингом имён, циклы разрешены.

```text
// math.lat
export fn square(x: int) -> int { return x * x; }

// main.lat
import { square as sq } from "./math.lat";
fn main() -> int { return sq(6); }
```

После линковки остаётся одна программа:

```latent
fn square(x: int) -> int { return x * x; }
fn main() -> int { return square(6); }
```

:::caution Статус модулей

Модули v1 уже в компиляторе: `latent::compile_files`, `latentc compile/check/bundle` и
ABI `latent_compile_files` для браузера, плюс поддержка в обоих движках web IDE.
Синтаксис, линковка и ограничения v1 — на странице [файловых модулей](./modules.md).
Ленивые чанки уже в проде — см. [гайд по фронтенду](./web-and-frontend.md).

:::

**Что это даёт.** Импорт — часть языка, а не рантайм-загрузчик: имена разрешаются на этапе
линковки, в WASM не нужен модульный резолвер, проект собирается без бандлера. Ленивые чанки
уменьшают стартовый бандл: `.wasm` ядра не скачивается, пока пользователь не запустил
вычисление.

**Где предел.** v1 узкий: только именованный импорт, без `export *`, `import * as ns`,
динамических импортов и пакетного менеджера. Экосистемы и npm нет; self-hosted компилятор
потребляет плоский `bundle`, а не дерево файлов.

**Попробовать.** <a href="/latent/demos/modules/">/latent/demos/modules/</a> — дерево файлов,
граф модулей, сборка и запуск. Теория: [ленивые чанки](./web-and-frontend.md), [web
IDE](../tooling/web-ide.md).

## 7. Два движка, один исходник

**Как это устроено.** Один `.lat` можно исполнить и скомпилировать. **Движок №1** — tree-walking
интерпретатор на JS: полный рантайм в браузере, включая каналы, `select`/`yield`, AI,
тензоры и контракты. **Движок №2** — компилятор на Rust, собранный в WASM: превращает
подмножество языка в валидный WASM-модуль. Playground выбирает движок сам: Run всегда
исполняет №1, host-фичи и ошибки №2 прозрачно откатываются на №1, а №2 отвечает за вкладку
WASM и явную компиляцию.

| | Движок №1 | Движок №2 |
|---|---|---|
| Что делает | **исполняет** программу | **компилирует** в WASM |
| Где живёт | `web-ide/compiler/` (JS) | `web-ide/compiler.wasm` (Rust) |
| Host-фичи (каналы, AI, тензоры) | да | нет, ошибка host-рантайма |
| `enum`, битовые операторы, блок-комментарии | нет | да |

```latent
fn main() -> int {
    print("same source, two engines");
    return 0;
}
```

**Что это даёт.** Один исходник живёт в двух ролях: учебный пример в браузере и WASM-ядро на
странице. Не нужно держать отдельный тулчейн для «поиграть» и «задеплоить»: playground — это
IDE, компилятор и рантайм, плюс self-repair.

**Где предел.** Два движка — двойная семантика и поддержка. Расхождения реальны: `7 / 2` —
`3.5` в №1 и `3` в №2, `"привет".length` — `6` против `12`, `[1] == [1]` — `true` против
`false`. №2 не исполняет код, а `float` в нём хрупок. Переносить код между движками нужно с
оглядкой на [таблицу различий](./wasm-and-execution.md#различия-движков).

**Попробовать.** Хаб <a href="/latent/demos/">/latent/demos/</a>. Теория: [два движка web
IDE](../specs/engines.md), [WASM и исполнение](./wasm-and-execution.md).

## Границы

**Где JS/TS лучше.** UI, DOM, формы, роутинг и состояние — территория React/Vue/Svelte с
DevTools, source maps и огромной экосистемой. npm, типы, готовые компоненты и найм: у Latent
почти нет стандартной библиотеки и пакетов, а модули — узкий v1. Строки и `f64`:
в JS это UTF-16 и `Float64Array` из коробки, в Latent — UTF-8 байты и невалидный `[float]`.
Долгоживущие приложения: GC в JS освобождает память, а в Latent она только растёт. И
JIT-friendly код: плотные числовые циклы JS уже быстрые.

**Где WASM не всегда быстрее.** Короткие вызовы: каждый переход границы — это `i32`/`f64` и
указатели, тысячи мелких вызовов медленнее одного JS-цикла. Малые данные: копирование
строки/массива в линейную память и обратно может стоить дороже вычисления. Старт: `fetch` +
`compile` + `instantiate` — десятки миллисекунд. Latent выигрывает предсказуемостью, а не
каждым бенчмарком.

| Компромисс | Статус |
|---|---|
| Нет GC и `free`, bump-аллокатор | **Остаётся**: предсказуемость важнее переиспользования |
| Модули/импорты | **v1 реализован** (Rust, CLI, ABI, движок №1); без `export *` и пакетов |
| Классы без наследования; нет исключений, `break`/`continue`, generics | **Остаётся** (коды возврата, `Result`) |
| `float` в №2 хрупок, `[float]` невалиден | **Остаётся**; используйте fixed point |
| Расхождения движков №1/№2 | **Смягчено** авто-фолбэком, таблица различий актуальна |
| Только `main` и `env.print` в ABI | **Остаётся**; экспорт функций — в дорожной карте |

## Как выбрать

| Сценарий | Latent? | Почему |
|---|---|---|
| Вычислительное ядро (парсинг, агрегация, валидация) | **Да** | маленький модуль, нет GC, предсказуемая память |
| Canvas/аудио/физика, стабильный кадр | **Да** | bump-аллокатор и отсутствие GC-пауз |
| AI-фичи в браузере (mock/гейтвей, эмбеддинги) | **Да, как прототип** | AI-примитивы в синтаксисе, офлайн-демо |
| Недоверенный или сгенерированный код | **Да** | WASM-песочница с одним импортом |
| Обучение, playground, «код в браузере» | **Да** | self-hosted компилятор без сервера |
| SPA, CRUD, DOM, формы | **Нет** | это работа JS/TS и фреймворков |
| Тяжёлый ML, `f64`-векторы, матрицы | **Пока нет** | нет `f64`-массивов и `i64`; считайте в JS |
| npm-библиотеки и большая команда | **Нет** | нет экосистемы и пакетов (модули — только v1) |
