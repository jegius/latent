# Переменные и типы

## `let`

```text
'let' IDENT (':' Type)? '=' Expression ';'
```

Инициализатор обязателен; тип выводится или задаётся аннотацией. Переменные
**изменяемы** — `let` не константа.

```latent
fn main() -> int {
    let count = 3;              // выведено: int
    let ratio: float = 2.5;     // явная аннотация
    let name: string = "Latent";
    let ready: bool = true;
    let values: [int] = [10, 20, 30];

    count = count + 1;          // присваивание разрешено
    print(count, ratio, name, ready);
    print(values.length);
    return count;
}
```

## Аннотации типов

| Запись | Смысл |
|---|---|
| `int`, `float`, `bool`, `string` | базовые типы |
| `[T]` | массив элементов `T` (например, `[int]`, `[[int]]`) |
| `fn(A, B) -> R` | тип функции |
| `Name` | пользовательский тип: класс или enum |
| `Name<T, ...>` | generic-аннотация; аргументы — типы или числа |
| `channel` | тип канала |

Особенности парсера аннотаций:

- generic-аргументы могут быть числами: `Embedding<1536>` → `Named("1536")`;
- `null` **нельзя** использовать как аннотацию (`fn f() -> null` — ошибка);
- `void`/`unit` синтаксически допустимы, но `return;` в функции с аннотацией
  `-> void`/`-> unit` даёт невалидный WASM — просто не указывайте `->`;
- union-типов (`int | string`) нет: `|` в аннотации — ошибка;
- `channel<int>` в аннотации **не** парсится как generic (спец-ветка `channel`);
  generic-форма работает в выражении: `channel<int>()`.

## Вывод типов

Система — Hindley–Milner-подобная: вызовы унифицируются, функции обобщаются,
аннотации необязательны.

- литерал-число в типовой системе всегда `float`;
- `int` и `float` **унифицируются в обе стороны** (поэтому `let x: int = 42`
  типизируется, хотя литерал — `float`);
- `bool`, `string`, `null`, `unit` унифицируются только сами с собой;
- `Named(a) ~ Named(b)` — только при равных именах; структурной типизации
  классов/enum нет;
- происходит occurs-check (`Бесконечный тип`).

Типчекер проверяет: неопределённые имена, условия `if`/`while` = `bool`,
iterable `for-in` = массив, аннотации `let`/параметров/возврата, арность обычных
вызовов. Он **не** проверяет: типы операндов арифметики и сравнений,
гомогенность массивов, арность builtins, поля классов.

## Представление типов в WASM (движок №2)

| Тип | WASM | Память |
|---|---|---|
| `int` | `i32` | 32-битное знаковое |
| `float` | `f64` | IEEE-754 double |
| `bool` | `i32` | `0`/`1` |
| `string` | `i32` | указатель на `[len u32][UTF-8]` |
| `[T]` | `i32` | указатель на `[len][элементы по 4 байта]` |
| `fn(...) -> R` | `i32` | `[индекс в таблице][env-указатель]` |
| класс/enum | `i32` | указатель на блок в линейной памяти |
| `null` | `i32` | `0` |

## Числа: важные правила движка №2

Кодогенератор выбирает инструкции по **синтаксическому** типу, а не по
результату типизации. Практические следствия:

- литерал с нулевой дробной частью (`1`, `2.0`, `1e3`) компилируется как
  `i32`; дробный (`1.5`, `3.14`) — как `f64`;
- `let x: float = 1.0;` даёт **невалидный WASM** (слот `f64`, значение `i32`);
- `let x: int = 1.5;` — тоже невалидно;
- смешанная арифметика `1.5 + 1` невалидна: оба операнда должны быть
  «дробными» (`1.5 + 2.5`) или приведены через `float(...)`;
- `%` для `float` всегда компилируется в `i32.rem_s` — невалидно;
- массив `[1.5, 2.5]` невалиден: элементы пишутся `i32.store`;
- функция без аннотации, возвращающая `float`, получает `i32`-сигнатуру —
  указывайте `-> float`.

Безопасные способы работы с `float`:

```latent
fn main() -> int {
    let pi: float = 3.14;                 // дробный литерал
    let half: float = float(1) / float(2); // явное приведение
    let square: float = 1.5 * 2.5;        // оба операнда дробные
    print(pi);
    print(half);
    print(square);
    return 0;
}
```

Приведения: `int(x)` (строка парсится, float усекается к нулю), `float(x)`,
`str(x)`, `sqrt(x)` (результат `float` — используйте его только в
float-контексте: `print(sqrt(16))` невалиден).

## Область видимости и тень

```latent
fn main() -> int {
    let x = 1;
    if (true) {
        let x = 2;      // новая переменная во внутреннем блоке
        print("inner:", x);
    }
    let x = 10;         // повторный let в том же блоке — просто новый слот
    print("outer:", x);
    return x;
}
```

## Ограничения движка №2

- Все случаи «компилируется, но WASM невалиден»: смешение `int`/`float`,
  float-массивы, float-поля классов, float-захваты замыканий, `-> int` с
  `return <float>`, `return;` в `-> void`.
- `null` нельзя аннотировать; `null` — это `0`, и `null == 0` истинно.
- Ошибки типов дают грубые позиции, а `expected`/`found` в тексте инвертированы
  (`let x: string = 42;` → `ожидалось 'float', найдено 'string'`).

## Отличия движка №1

- Все числа — `float`: `7 / 2 == 3.5`.
- `1.0` и `1` неразличимы; float-ограничений кодогена нет.
- `print(true)` → `true`, `print(null)` → `null`.
