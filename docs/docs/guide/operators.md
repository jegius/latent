# Операторы и приоритеты

## Полная таблица

Приоритеты — числа связывания Pratt-парсера: чем больше число, тем «крепче»
оператор. Унарные операторы имеют приоритет `95`.

| bp | Операторы | Ассоциативность | Кодоген (движок №2) |
|---|---|---|---|
| 2 | `=` | правая | `local.set`/`i32.store`/`f64.store` |
| 2 | `<-` (инфикс) | правая | **ошибка host-рантайма** |
| 10 | `\|\|` | левая | короткое замыкание через `if` |
| 20 | `&&` | левая | короткое замыкание |
| 30 | `==`, `!=` | левая | `i32.eq`/`f64.eq`; строки — `str_eq` |
| 40 | `<`, `>`, `<=`, `>=` | левая | `i32.lt_s`/`f64.lt`; строки — сравнение **указателей** |
| 50 | `\|`, `^` | левая | `i32.or`/`i32.xor` |
| 60 | `&` | левая | `i32.and` |
| 70 | `<<`, `>>` | левая | `i32.shl`/`i32.shr_s` |
| 80 | `+`, `-` | левая | `i32.add`/`f64.add`; `+` со строкой — конкатенация |
| 90 | `*`, `/`, `%` | левая | `i32.*`, `f64.*`; `%` всегда `i32.rem_s` |
| 95 | `-x`, `!x`, `<-ch`, `await x` | префикс | `0-x`/`f64.neg`, `i32.eqz`, ошибка, passthrough |

Постфиксные операторы (вызов `f(x)`, индексация `a[i]`, поле `obj.f`) — самые
крепкие.

## Арифметика

```latent
fn main() -> int {
    let a = 17;
    let b = 5;
    print(a + b, a - b, a * b);
    print("div:", a / b);   // движок №2: 3 (усечение)
    print("rem:", a % b);   // 2
    print(2 + 3 * 4);       // 14
    print((2 + 3) * 4);     // 20
    return 0;
}
```

- `/` для целых — `i32.div_s` (усечение к нулю), деление на ноль — trap;
- `%` — `i32.rem_s`, для `float` **не работает** (невалидный WASM);
- переполнение `i32` не диагностируется (оборачивается);
- в движке №1 все числа float, поэтому `17 / 5 == 3.4`.

## Сравнения

```latent
fn main() -> int {
    let x = 7;
    print(x == 7, x != 7, x < 10, x > 0, x <= 7, x >= 7);
    return 0;
}
```

- `==`/`!=` для строк — сравнение **по содержимому** (`str_eq`);
- `<`/`>`/`<=`/`>=` для строк сравнивают **указатели**, а не содержимое —
  для лексикографического сравнения нет builtin;
- `==` для массивов в движке №2 сравнивает указатели (в движке №1 —
  структурно);
- сравнение `float` и `int` операндов даёт невалидный WASM.

## Логические операторы

```latent
fn main() -> int {
    let a = true;
    let b = false;
    if (a && !b) {
        print("and-not");
    }
    if (a || b) {
        print("or");
    }
    print(!0, !1); // !x = (x == 0): 1, 0
    return 0;
}
```

`&&`/`||` — с коротким замыканием (правая часть не вычисляется, если результат
известен). `!` — логическое НЕ через `i32.eqz`, поэтому `!5 == 0`, `!0 == 1`.

## Битовые операторы и сдвиги

```latent
fn main() -> int {
    print(1 << 4);   // 16
    print(16 >> 2);  // 4 (арифметический сдвиг)
    print(7 & 3);    // 3
    print(1 | 2);    // 3
    print(5 ^ 1);    // 4
    return 0;
}
```

Битовые операторы есть **только в движке №2**; JS-интерпретатор падает на `<<`,
`&` и т.п. с ошибкой лексера.

## Присваивание

```latent
fn main() -> int {
    let x = 10;
    x = x + 5;          // присваивание имени
    let arr = [1, 2, 3];
    arr[0] = 100;       // присваивание элементу массива
    return x + arr[0];
}
```

- цель присваивания — имя, `arr[i]` или `obj.field`;
- выражение присваивания возвращает присвоенное значение;
- составных присваиваний (`+=`, `-=`, `*=`, `/=`, `%=`) **нет** — лексер
  специально разбивает `/=` на `/` и `=`;
- инкремента/декремента (`++`/`--`) нет.

## Каналы

`ch <- v` (отправка) и `<-ch` (приём) — операторы, но в движке №2 оба дают
ошибку host-рантайма; см. [конкурентность](./concurrency.md).

## Ограничения движка №2

Невалидный WASM (компиляция проходит, `WebAssembly.validate()` — нет):

- `%` с `float`-операндами;
- сравнение `float` с `int` (`1 < 1.5`, `a > 3.0` при `a: float`);
- смешанная арифметика `int`/`float`;
- `x = 2.5`, если `x` объявлена как `int` (и наоборот).

Также: `true + true == 2` (bool — это i32) — типизируется и компилируется, но
семантически это арифметика над `0/1`.
