# Два движка web IDE

Браузерная IDE (`web-ide/`) содержит **две реализации** языка. Понимание того,
какая из них выполняется, критично: они по-разному себя ведут.

| | Движок №1 | Движок №2 |
|---|---|---|
| Что это | tree-walking интерпретатор на JS | Rust-компилятор Latent → WASM |
| Где | `web-ide/compiler/` | `web-ide/compiler.wasm` (сборка `src/`) |
| Что делает | **исполняет** программу | **компилирует** в WASM (не исполняет) |
| Загружается | всегда (модули ES) | лениво, по кнопке/вкладке |
| Ошибки | JS-исключения (английский) | русские тексты компилятора |
| Host-фичи (AI, каналы, тензоры) | ✅ | ❌ ошибка «требует host-рантайма» |

## Движок №1: JS-интерпретатор

Пайплайн (`web-ide/compiler/run.js`):

1. `tokenize(source)` — `compiler/lexer.js`;
2. `new Parser(tokens).parseProgram()` — `compiler/parser*.js`;
3. `new Interpreter(program, output).run()` — `compiler/interpreter*.js`.

Особенности:

- **Нет тайпчекера**: аннотации типов разбираются и отбрасываются.
- `main` обязательна (`Function 'main' not found`), вызывается без аргументов.
- После `main` дожидаются все горутины планировщика
  (`runScheduler`); если задачи остались — ошибка `Deadlock: ...`.
- Затем исполняются `test`-блоки (`runTests`), результаты складываются в
  `interpreter.testResults`, но **в UI не отображаются**.
- Защита от зависаний: лимит итераций циклов (1 000 000), лимит планировщика
  (10 000 000).
- «Байткод» движка №1 (`compiler/loader.js`) — это просто UTF-8 байты
  исходника; вкладка WASM показывает их hex.
- AI-функции включаются только при «Run with AI» (`interpreter.enableAI()`);
  иначе `ai_infer`/`ai_embed`/`ai_stream` бросают
  `AI is not enabled. Use "Compile & Run with AI" button.`

Состав по зонам ответственности: `lexer.js`, `parser-*.js`, `interpreter*.js`,
`value-utils.js`, `oop.js`, `environment.js` (каналы, Promise-подобные
значения), `ai-config.js`, `ai-gateway.js`, `repair.js`, `analysis.js`,
`wasm-loader.js`, `loader.js`, `run.js`.

## Движок №2: Rust-компилятор в WASM

- Загрузчик: `web-ide/compiler/wasm-loader.js`.
- Кэширование: Cache API, имя кэша `latent-compiler-v1`, URL `compiler.wasm`
  (можно передать `opts.url`).
- Инстанцирование: `WebAssembly.instantiate(bytes, imports)` (не
  `instantiateStreaming` — dev-серверы часто отдают неверный MIME).
- ABI: `latent_alloc(src_len)` → запись исходника в память →
  `latent_compile(ptr, len)` → `[status][len][payload]`
  ([C-ABI](../reference/wasm-abi.md#c-abi-компилятора-движок-2-в-браузере)).
- Если `compiler.wasm` недоступен/не содержит ABI — загрузчик возвращает
  `null`, IDE продолжает работать на движке №1 (graceful degradation).
- Движок №2 **не исполняет** скомпилированный WASM: он только компилирует и
  отдаёт байты для показа/скачивания.

## Как выбирается движок

| Действие | Что используется |
|---|---|
| `Run` / `Compile & Run` (`Ctrl/⌘+Enter`) | **движок №1** исполняет программу; если движок №2 уже загружен, `compile()` для вкладки WASM идёт через него |
| `Run with AI` (`Ctrl/⌘+Shift+Enter`) | движок №1 с AI + self-repair (до 3 попыток) |
| `Check` | движок №1: `checkSyntax` (токенизация + парсинг) |
| Кнопка `Engine #2` | лениво грузит движок №2 и компилирует текущий код; результат — во вкладке WASM |
| Вкладка `WASM` | при первом открытии инициирует загрузку движка №2 |
| Статус-бар (`status-engine`) | `engine #1 (interpreter)` или `engine #2 (rust→wasm)` |

Важное следствие: **«Run» всегда исполняет движок №1**, даже если движок №2
загружен. Чтобы увидеть ошибки/поведение Rust-компилятора, нажмите
`Engine #2` (или откройте вкладку WASM) и смотрите сообщение в панели вывода.

Код-центричное поведение `CompilerService`
(`web-ide/services/compiler-service.js`):

- `compile(source)` — если `wasmCompiler` загружен, компилирует им, иначе
  отдаёт «байткод» движка №1;
- `compileAndRun(source)` — `compile()` + `runLatent()` (движок №1) —
  поэтому исполнение всегда №1;
- `ensureWasmCompiler()` — однократная ленивая загрузка с кэшем попытки;
- `hasWasmCompiler()` — для статус-бара.

## Поддержка фич (проверено)

| Фича | №1 | №2 |
|---|---|---|
| `let`, `if/else`, `while`, `for`, `for-in` | ✅ | ✅ |
| функции, рекурсия, замыкания | ✅ | ✅ |
| массивы, индексация, `push`/`pop`/`length`, `len` | ✅ | ✅ |
| строки, `+`, `==`, `s[i]`, `.length` | ✅ | ✅ |
| классы/`new`/`this`/методы | ✅ | ✅ (метод — только на переменной класса) |
| `enum`/`match` | ❌ enum нет | ✅ (float-payload ⚠️) |
| `async`/`await` | ✅ | ✅ (`await` — passthrough) |
| `channel`, `<-`, `select`-ожидание, `yield` | ✅ | ❌ host / первая ветка |
| `tensor`, `semantic`, `matmul`, AI, контракты | ✅ | ❌ host |
| побитовые операторы | ❌ лексер | ✅ |
| `str`/`int`/`float`/`sqrt` | ❌ | ✅ |
| `assert`/`assert_eq` | ✅ | ✅ (trap) |
| `test`-блоки | ✅ исполняются | ⚠️ компилируются, не исполняются |

## Семантические расхождения Rust-компилятор vs JS-движок

Проверено прогоном обоих движков на одинаковых фрагментах. Это ключевая
таблица для тех, кто переносит код между движками.

| Конструкция | Rust (WASM) | JS (движок №1) | Вердикт |
|---|---|---|---|
| `7 / 2` | `3` (`i32.div_s`) | `3.5` (всегда float) | расхождение |
| `"привет".length` | `12` (байты UTF-8) | `6` (UTF-16 code units) | расхождение |
| `"abc"[1]` | `98` (байт) | `"b"` (символ) | расхождение |
| `[1] == [1]` | `0` (указатели) | `1` (структурное) | расхождение |
| `let a=[1]; a == a` | `1` | `1` | совпадает |
| `assert_eq("a"+"b", "ab")` | trap (указатели) | ok (структурно) | расхождение |
| `assert_eq([1], [1])` | trap | ok | расхождение |
| `print(true)` | `1` | `true` | расхождение |
| `print(null)` | `0` | `null` | расхождение |
| `print([1,2])` | `1024` (указатель) | `[1, 2]` | расхождение |
| `print(1.5)` | `1.500000` | `1.5` | расхождение |
| `print("a", 1)` | две строки: `a`, `1` | одна строка: `a 1` | расхождение |
| `let x = 1 return x` (без `;`) | ошибка парсинга | ok (ASI-подобно) | расхождение |
| `1e3` | `1000.0` | `1` (затем идентификатор `e3`) | расхождение |
| `1.2.3` | ошибка парсинга | `1.2` (лексер съедает как число) | расхождение |
| `"a\q"` | ошибка escape | `"aq"` | расхождение |
| `enum E { A, B }` | ok | ошибка (`Unexpected token '{'`) | Rust-only |
| `1 << 3`, `7 & 3` | ok | ошибка лексера | Rust-only |
| `/* … */` | ok (вложенные) | ошибка | Rust-only |
| `for (let c in "abc")` | ошибка типов | 3 итерации | JS-only |
| `match` с void-ветками | invalid WASM | ok | JS-only |
| `match b { case true: … }` | ошибка парсинга | ok | JS-only |
| `match 1 { case 1: { … } }` (блок-ветка) | ошибка | ok (`BlockExpr`) | JS-only |
| `match 1 { case 1: 10 default: 0 }` (без запятой) | ошибка | ok | JS-only |
| класс: метод без `fn`, поле без `;` | ошибка | ok | JS-only |
| вложенный `fn` | `Unknown function` | работает | JS-only |
| `spawn x + 1` | компилируется: выражение вычисляется inline | ошибка парсинга | расхождение |
| `spawn w()` | inline-вызов | горутина | расхождение |
| `select` | тело 1-й ветки | блокирующий выбор готового канала | расхождение |
| `yield` | no-op | уступает планировщику | расхождение |
| `await` не-Promise | ошибка типов | тождество | расхождение |
| `async fn` | обычная функция | `resolvedPromise` | расхождение |
| дубликат `fn f` | компилируется молча | вторая перезаписывает первую | совпадает по эффекту |
| top-level `let` | не компилируется | `Undefined variable` | совпадает (оба не работают) |
| `@forall`/`@ai_contract` над `fn` | цель декоратора не регистрируется → `Unknown function` при вызове | работает (декоратор игнорируется) | расхождение |
| `test` на верхнем уровне | не исполняется | исполняется | расхождение |
| `ai_generate!("p")` | ошибка кодогена | `Undefined variable 'ai_generate'` | оба не работают |
| `semantic("x")[0]` | ошибка host-рантайма | векторное значение | JS-only |

## Что происходит при ошибках

- Движок №1: исключение перехватывается в `handleCompile`; в консоль выводится
  `Error: <сообщение>`, вкладка WASM — `Compilation failed: ...`.
- Движок №2 (кнопка Engine #2): ошибка компилятора пишется во вкладку WASM как
  `Engine #2 error:\n<текст>`; статус `✗ Engine #2 error`.
- Self-repair (только «Run with AI»): при ошибке движка №1 модель/детерминированный
  ремонт пытается исправить исходник (до 3 попыток); при успехе редактор
  обновляется, в консоль пишется `[Self-repair] Fixed after N attempt(s)`.
  Детерминированный ремонт умеет: поставить пропущенную `;` перед `}` по
  номеру строки из диагностики и дописать несбалансированные `}`.

## Ограничения и подводные камни

- Поставляемый `web-ide/compiler.wasm` **старше** текущих `src/`: в нём нет
  memory-builtins (`alloc`, `load8`, ...), хотя в `src/` они есть. Смотрите
  [bootstrap](../tooling/bootstrap.md) о пересборке.
- Движок №2 не исполняет код: «Run» не проверит поведение WASM.
- Движок №1 не поддерживает `enum`, поэтому примеры с `enum` в IDE не
  запустятся (только компилируются движком №2).
- Кодировка ввода — UTF-8; вывод `env.print` — строка `[len][utf8]`.
