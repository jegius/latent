# Ограничения и отложенные задачи

Этот реестр — не список обещаний. Здесь собрано то, что действительно ограничивает
Latent сегодня: ошибки, которые лучше не показывать новым пользователям, обходные
пути и работа, которую мы сознательно отложили. Приоритеты означают цену ошибки,
а не «когда руки дойдут».

- **P0** — ошибка ломает доверие к компилятору или может испортить данные.
  Исправлять до того, как звать новых пользователей.
- **P1** — мешает писать реальные программы; обходной путь есть, но он неочевиден.
- **P2** — ограничение языка или продукта; жить можно, но это видно.
- **P3** — осознанный выбор или то, что в обозримом плане не появится.

Каждая строка имеет идентификатор `Lxx`. В [дорожной карте](./roadmap.md) те же
идентификаторы привязаны к фазам и критериям готовности. Если добавляете
ограничение в документацию, добавьте его и сюда — иначе список снова разойдётся
с кодом.

## P0. Доверие к компилятору и сохранность данных

| ID | Ограничение | Что происходит | Обход сейчас | Куда идём |
|---|---|---|---|---|
| L01 | Движок №2 выдаёт невалидный WASM на части программ | float-литералы с нулевой дробной частью, `let` с «чужим» типом, `[1.5]`, смешанная арифметика, float-поля/захваты, `return;` в `unit`, void-вызов как значение, `match` с void-ветками, `new` без `init`, void-метод в позиции инструкции | `WebAssembly.validate()` на хосте; документация помечает такие блоки `// Не компилируется…` | компилятор валидирует собственный модуль и возвращает ошибку с позицией; типовой кодоген |
| L02 | Нет проверки границ и «безопасного» режима | `a[N]` читает/пишет за пределы; `pop()` на пустом массиве читает `arr[-1]`; `push` на строке портит память; `len()` без аргумента читает адрес 0 | не выходить за границы вручную; запускать недоверенный код в Worker | режим `safe` с проверками (trap с сообщением), отдельный `raw` для низкоуровневого кода |
| L03 | Строки и массивы сравниваются не так, как ожидает пользователь | `< > <= >=` для строк сравнивают указатели; `assert_eq` строк/массивов сравнивает i32-значения, результат зависит от дедупликации литералов | сравнивать длину и байты вручную | сравнение по содержимому для `string`/`[T]`, отдельное сравнение указателей |
| L04 | BOM в начале файла ломает лексер | ошибка с колонкой `4294967295`, debug-сборка `latentc` может паниковать | сохранять UTF-8 без BOM | пропускать `U+FEFF` и не переполнять колонку |
| L05 | Арность встроенных функций не проверяется | лишние аргументы молча игнорируются (`assert`, `len`, `str`, …); недостающие читают мусор | читать сигнатуры в справочнике | проверка арности и типов аргументов в тайпчекере |
| L06 | Крайние значения чисел и trap'ы без диагностики | `i32_to_str(i32::MIN)` переполняется; `f64_to_str` падает при `|x| ≥ 2^31`; деление/остаток на 0 и `i32::MIN / -1` дают wasm-trap без номера строки | избегать крайних значений; проверять делитель | корректное форматирование, trap с позицией и кодом |
| L07 | Движок №2 молча подменяет семантику конкурентности | `spawn` исполняется последовательно, `select` — первая ветка, `yield` — no-op, `await` — passthrough, top-level код и `test`-блоки не эмитятся | не компилировать host-конструкции в №2 | ошибка компиляции вместо суррогата либо явный флаг «эмуляция» |
| L08 | Движки расходятся в наблюдаемом поведении | `7 / 2` — `3.5` в №1 и `3` в №2; длина строки — UTF-16 против UTF-8; `[1] == [1]` — `true` против `false`; float; `enum` в №1 | таблица различий и авто-фолбэк playground | единая спецификация и parity-тесты на каждый пример |
| L09 | Нет «диагностики компилятора» для невалидного модуля | невалидный WASM обнаруживает только хост; ошибка выглядит как `CompileError` без исходной строки | `validate()` в своём загрузчике | встроенная валидация + коды ошибок |

## P1. Реальное использование

| ID | Ограничение | Что происходит | Обход сейчас | Куда идём |
|---|---|---|---|---|
| L10 | Экспортируется только `main`, импортируется только `print` | нельзя отдать `parse()`/`sort()` в JS; нет DOM, `fetch`, времени, случайных чисел | один вход на модуль; обёртки на JS | `export fn` с параметрами и результатами, список host-импортов с версией |
| L11 | Нет освобождения памяти, арен и GC | bump-аллокатор только растёт; долгая страница пересоздаёт экземпляр | переиспользовать буферы; новый экземпляр | `arena`/`reset`, затем — освобождение и/или ownership-lite |
| L12 | Нет исключений и эргономичного `Result` | ошибки — коды возврата, `assert` — trap, нет `?` | `Result`-подобные значения вручную | `Result<T,E>` + `?`, граница ABI без trap'ов |
| L13 | Управляющие конструкции неполные | нет `break`/`continue`, `switch`, `if`-выражения, тернарника, составных присваиваний, `for (;;)` без `let` | `while` + флаги | `break`/`continue`, `if`-выражение, `+=` и родственные |
| L14 | Модули v1 узкие | нет `export *`, re-export, `import * as`, динамического импорта, пакетов, каталогов в IDE, namespace-квалификации | импортировать по одному имени, плоские файлы | modules v2: re-export, namespace, каталоги, пакеты |
| L15 | Конкурентность кооперативная и без отмены | один поток, нет вытеснения; долгий цикл блокирует остальных; очередь канала не ограничена; `send` не блокируется; `select` опрашивает ветки по порядку; нет таймаутов, отмены, приоритетов, `select` с отправкой | `yield`/`recv` в горячих циклах; Worker снаружи | bounded channels, select send/default/timeout, отмена, честная очередь, structured concurrency |
| L16 | AI-примитивы — host-only mock | эмбеддинги хэш-произвольны; нет реального embeddings-эндпоинта; `ai_generate!` не исполняется JS-движком; нет схем, ретраев, учёта токенов, backpressure | gateway только для `ai_infer`; демо офлайн | типизированные AI-значения, реальные эмбеддинги, стриминг с backpressure, `ai_generate!` через lowering |
| L17 | Self-host ограничен подмножеством и скоростью | часть host-only корпуса не компилируется/зависает; нет модулей (только `bundle`); нет source maps и оптимизаций; seed — доверенный снимок; обновление seed требует Rust | проверенные samples; timeout в Worker | покрытие корпуса, bundle-модули, speed pass, обновление seed без Rust |
| L18 | Нет `i64` и `f64`-массивов | эмбеддинги, точная арифметика и матрицы — только fixed-point или JS | fixed-point, `i32` | `i64`, `[f64]`, `f64`-векторы в ABI |
| L19 | Песочница не ограничивает CPU и память | wasm исполняется до `terminate`; `memory.grow` виден хосту, но не лимитирован языком; нет fuel | Worker + таймаут + лимит страниц на хосте | опциональный fuel/epoch, лимит памяти в helper'е |
| L20 | Web IDE: плоское дерево и память вкладки | нет каталогов, правки не сохраняются после reload; engine #2 не исполняет WASM | один уровень файлов; экспорт вручную | каталоги/workspace, сохранение, запуск WASM-модуля |
| L21 | Инструменты расходятся | IDEA-плагин содержит старую копию `compiler.wasm`; LSP даёт диагностику только через компиляцию; нет отладчика | обновлять wasm скриптом; логи | синхронизация артефактов, semantic LSP, DAP |
| L22 | Нет стандартной библиотеки и коллекций | только встроенные `len/push/pop/...`; нет map/set, сортировки, работы со строками сверх базовой | писать вручную | небольшая `std`-библиотека на Latent после стабилизации ядра |
| L23 | Нет source maps, name-секции и символов | отладка по указателям и `console.log`; trap без функции | логирование | name-секция, source maps, trap-трейсы |
| L24 | `test`-блоки не эмитятся движком №2 | тесты — движок №1; раннера в CLI нет | запускать через IDE | раннер тестов и эмиссия/интерпретация тестов в обоих движках |
| L25 | Parity-матрица неполная | 64/65 кейсов; расхождения движков документированы, но не все автоматизированы | ручная таблица | каждый документированный пример — parity-тест в CI |
| L41 | Аннотации типов разбираются, но не проверяются | `let x: int = 1.5;` не диагностируется, а кодоген получает чужой valtype | не полагаться на аннотации | проверять аннотации в тайпчере и использовать их в кодогене |
| L42 | Декораторы и top-level код не регистрируются/не эмитятся | `@decorator fn` парсится, но вызов даёт `Unknown function`; top-level `let`/вызовы и `test`-блоки в №2 не попадают в модуль | не использовать декораторы в №2; тесты — в IDE | регистрировать декораторы или честно запрещать; эмитить top-level код |
| L43 | Странности областей видимости и возврата | `return` внутри `spawn` возвращает из объемлющей функции; `return` в ветке `match` не парсится; `obj.length` перехватывает поле класса; `this` вне метода — эвристика; `for` с не-bool условием не диагностируется | избегать этих конструкций | единые правила возврата, отдельный `length` для полей, диагностика `this`/`for` |
| L44 | `null` — это `0`, null-safety нет | `null` неотличим от нулевого указателя/числа; разыменование — trap или мусор | проверять вручную | `Option<T>`/nullable-типы и безопасная навигация |
| L45 | Длина строки различается между движками | в №1 — UTF-16 code units, в №2 — UTF-8 байты | использовать `len` только для байтов в №2; проверять оба движка | одно определение + `byte_len`/`chars` |
| L46 | Нет doc-комментариев и генерации документации из кода | документация пишется отдельно, символы не имеют описаний | Markdown вручную | doc-комментарии `///` и извлечение в LSP/сайт |
| L47 | Аргументы `main` не зафиксированы как ABI | передача i32/f64/указателей работает, но не является контрактом | считать `main()` без аргументов переносимым | версионированный ABI `main`/экспортов |

## P2. Ограничения языка и продукта

| ID | Ограничение | Комментарий |
|---|---|---|
| L26 | Нет пакетов, реестра, npm-пакета, TS-типов, плагинов Vite/Webpack | модули v1 — только файлы проекта |
| L27 | Нет наследования, интерфейсов, трейтов, пользовательских generic-типов | классы — поля/методы/`init`; `Name<T>` только для встроенных |
| L28 | Нет перегрузки функций/операторов | дубликаты `fn` не диагностируются, последняя сигнатура перетирает |
| L29 | Лексические ограничения | ASCII-идентификаторы; нет hex/bin/underscore-литералов, `NaN`/`Infinity`, `\u{...}`, `\r`, `\0`; `1.` — не число; целые > 2^53 теряют точность |
| L30 | Нет строковой интерполяции, `switch`, тернарника, `const`, `defer`, именованных аргументов, doc-комментариев | всё это влияет на читаемость и тулинг |
| L31 | Нет настоящего `async` | в №1 — Promise-подобная имитация, в №2 — passthrough; нет планировщика задач |
| L32 | Нет WASI, потоков, atomics, shared memory | только `wasm32` без окружения; Worker — на уровне хоста |
| L33 | Нет инкрементальной компиляции и wasm-opt | маленькие программы быстрые, большие — нет; размер модуля не оптимизируется |
| L34 | Нет кодов ошибок и единого формата позиции | сообщения текстовые, иногда без `L:C`, рантайм показывает мангленные имена |
| L35 | Философия «маленького ядра» ограничивает stdlib и экосистему | осознанно; см. [философию](../intro/philosophy.md) |

## P3. Осознанно вне плана (или очень далеко)

| ID | Что | Почему |
|---|---|---|
| L36 | Сборка мусора | Latent исследует детерминированную память; GC противоречит нише |
| L37 | Полноценный UI-фреймворк и DOM | это работа JS/TS; Latent — вычислительное ядро |
| L38 | Большая стандартная библиотека «как в Go» | ядро важнее охвата; сначала стабильность ABI |
| L39 | Наследование классов | композиция и `enum`/`match` покрывают сценарии; наследование усложняет layout |
| L40 | Пакетный реестр в стиле npm | сначала модули v2 и воспроизводимая сборка |

## Как поддерживать список

1. Новое ограничение сначала появляется в документации темы (раздел
   «Ограничения движка №2» или «Ограничения»).
2. Затем — здесь, с `Lxx`, приоритетом и обходным путём.
3. В [дорожной карте](./roadmap.md) `Lxx` попадает в фазу и критерий готовности.
4. Когда ограничение снято, строка не удаляется сразу: она переезжает в раздел
   «Снято» с версией и тестом, который это проверяет.
