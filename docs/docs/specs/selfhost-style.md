# Функциональный стиль `selfhost/src/*.lat`

Этот документ — соглашение о стиле для **исходников self-hosted
компилятора** на подмножестве Latent (`selfhost/src/*.lat`, генерируемый
`selfhost/shc.lat`). Он не требует переписать компилятор в функциональном
языке: `shc.lat` остаётся процедурным компилятором с состоянием в линейной
памяти. Цель — **функционально чистые границы**: предсказуемые запросы,
явные эффекты и отсутствие скрытых глобальных мутаций.

Правила применяются к новому и изменяемому коду. Легаси-код приводится к ним
по мере декомпозиции, а не «большим взрывом».

## 1. Модель: запросы, эффекты и состояние

В подмножестве Latent нет структур, массивов-значений и замыканий в роли
штатной структуры данных компилятора. Всё состояние — **линейная память**,
размеченная в `00_abi.lat`. Поэтому «функциональность» здесь означает не
отсутствие памяти, а **дисциплину доступа** к ней.

Три категории функций:

| Категория | Что делает | Имя | Примеры |
|---|---|---|---|
| **Запрос (query)** | Только читает аргументы и память, ничего не пишет | `get_*`, `find_*`, `is_*`, `*_len`, `nf`, `tok_kind`, `tok_val` | `find_local`, `find_str`, `name_eq`, `local_tp` |
| **Эффект (effect)** | Пишет в явно названный сток: буфер, таблицу, слот состояния | `emit_*`, `ev_*`, `b*`, `add_*`, `set_*`, `scan_*`, `store*` | `ev`, `bput`, `add_local`, `set`, `scan_classes` |
| **Смешанная** | Запрос + эффект | **запрещена**; разделить на `find_*` + `add_*` | — |

Правило: **если функция пишет — это видно из её имени и из её сигнатуры**.
Читатель не должен догадываться, что `get_x()` на самом деле создаёт запись,
а `check_y()` двигает курсор.

### 1.1. Где разрешено состояние

Единственный источник истины о памяти — `00_abi.lat` (карта адресов и
аксессоры `get`/`set`). В остальных частях:

* **никаких числовых адресов** (`load32(2260992 + ...)`) — только именованные
  функции карты (`ST()`, `TSTK()`, `ERRB()` …);
* **никаких новых глобальных слотов** без записи в карту `00_abi.lat`:
  адрес, размер, stride, владелец, время жизни;
* слот состояния — это **явно переданное состояние**, а не скрытая
  переменная: `get(0, PC)` читается как «поле PC состояния компилятора».

### 1.2. Владелец слота и направление прохода

У каждого слота один владелец на фазу компиляции:

| Фаза | Кто пишет | Кто читает |
|---|---|---|
| `tokenize` | `KIND`, `TVAL`, `TLEN`, `NT` | `scan_*`, `tc_*`, `compile_*` |
| `scan_*` (классы/enum/сигнатуры/лямбды) | `CLN*`, `FLD*`, `METH*`, `VARN*`, `LAM*`, `CAP*`, `FNOFF/FNLEN/FNNP`, `FNRET` | `tc_*`, `compile_*` |
| `tc_*` (тайп-чек) | `TV_*`, `FRETTY`, `ERRB`, `status` | `compile_*` (только `status`) |
| `compile_*` (кодоген) | `FNB`, `CODEB`, `BODYC`, `CODEOF/CODELEN`, `DATAB`, `status` | `build_module` |
| `build_module` | `OUTB` | хост (ABI) |

Один проход не должен «подчитывать» данные, которые ещё не заполнены, и не
должен писать в таблицы предыдущей фазы. Нарушение этого правила — главный
источник плавающих багов и расхождений stage1/stage2.

## 2. Чистые функции

Функция считается **чистой относительно компилятора**, если её результат
зависит только от аргументов и от документированных слотов, которые она
читает, и она не меняет память. Требования:

1. **Никаких скрытых флагов.** Не заводите `let failed = 1;` «на весь
   компилятор». Ошибка — это документированный канал `status`/`ERRB`
   (`45a_tc_core.lat`), а не побочная глобальная переменная.
2. **Предикаты не мутируют.** `is_ident_kind`, `is_for_in`, `is_field_start`,
   `is_index_assign` обязаны быть безопасны для повторных вызовов.
3. **Поиск отдельно от вставки.** `find_*` возвращает индекс или `-1` и
   ничего не добавляет. `add_*` добавляет и возвращает индекс. Не смешивайте
   их в `find_or_add_*` — иначе появляется скрытый эффект.
4. **Идемпотентность запросов.** Два вызова `tok_kind()` подряд без `next_token`
   дают одно и то же; два вызова `find_local` — один и тот же индекс.
5. **Явные аргументы.** Передавайте `offset`, `len`, `slot`, `class` явно.
   Не читайте «глобальную текущую функцию», если её можно передать
   параметром; `CURFI()` — исключение для рекурсивных хелперов кодогена.

Примеры из кода:

```text
// Чистый запрос: ничего не пишет, возвращает -1, если не найдено.
fn find_local(off, ln) -> int { ... }

// Явный эффект: добавляет запись и возвращает слот.
fn add_local(off, ln, idx) -> int { ... }

// Чистый запрос к состоянию.
fn nf() -> int { return get(0, 2); }

// Явный эффект эмиссии: пишет байт в тело текущей функции.
fn ev(b) -> int { return bput(FNB(), b); }
```

## 3. Побочные эффекты

Эффект допустим, если он:

* пишет **только в документированный сток** (буфер, таблицу, слот);
* назван так, что эффект виден (`emit_`, `ev_`, `bput`, `add_`, `set_`,
  `scan_`, `store`);
* не меняет чужие стоки «по пути»;
* не переупорядочивает эмиссию байтов без теста на фиксированную точку.

Разрешённые стоки кодогена:

| Сток | Назначение |
|---|---|
| `FNB` | тело текущей функции (эмиссия инструкций) |
| `BODYC` | финальное тело функции / тело хелпера |
| `CODEB` | все тела функций |
| `SCRB` | скретч секции WASM |
| `OUTB` | готовый модуль |
| `DATAB` | data-секция строковых литералов |
| таблицы `00_abi` | регистрация классов/enum/лямбд/типов |
| `status`, `ERRB` | ошибки компиляции |

Правила:

* **Эмиссия — это эффект, а не запрос.** `emit_*` может возвращать `0` или
  длину, но не должен использоваться в арифметике как «чистое» значение.
* **Порядок байтов семантичен.** Нельзя «оптимизировать» эмиссию, меняя
  порядок инструкций, без дифференциальных тестов и проверки
  `stage2 === stage3`.
* **Никаких скрытых аппендов.** `find_str` не должен добавлять строку;
  добавление — только `add_str`. Это уже соблюдено в `30_syntax.lat`, и это
  правило нужно сохранять.
* **Сброс состояния — в драйвере.** `90_driver.lat` инициализирует слоты
  (`set(0, ...)`, `set_ncls(0)` …). Части не должны полагаться на «память
  была нулевой»: при повторном прогоне в одном инстансе это неверно.

## 4. Ошибки как явный канал

Ошибка — тоже эффект, но у неё один канал на весь компилятор:

1. `status` (слот 4) выставляется в `1`;
2. текст пишется в `ERRB` в формате `[len u32 LE][utf8]`;
3. драйвер проверяет `status` **после каждой фазы** и возвращает
   отрицательную длину, а не невалидный WASM.

Правила:

* не глотайте `err()`: если функция может не найти сущность, она возвращает
  `-1`, а вызывающий решает, ошибка это или нет;
* не пишите в `ERRB` напрямую из случайных мест — используйте
  `tcerr_msg`/`tcerr`/`err_named`;
* не используйте `0` как «нет ошибки, но и результата нет» — для поиска есть
  `-1`, для ошибки — `status`;
* текст ошибки — часть наблюдаемого поведения (тесты сравнивают stage1 и
  stage2 посимвольно). Меняя текст, обновляйте тесты.

## 5. Размер и декомпозиция

* **Файл ≤ 300 строк** — жёсткое требование (проверяется в ревью и в
  `decomposition-plan.md`).
* **Функция ≤ 40–50 строк** — мягкое требование. Если функция длиннее,
  выделите именованный хелпер по ответственности, а не по «чтобы влезло».
  Исключения — генераторы байтовых тел (`helper_*`), где длина обусловлена
  форматом WASM; они должны быть разбиты по хелперам и прокомментированы.
* **Одна часть — одна ответственность.** Границы: lexer, syntax (курсор /
  локали / строки), class, enum, lambda (скан / эмиссия), emit (ядро /
  вызовы / host / float / primary / postfix / match / операторы), typecheck
  (ядро / выражения / паттерны / инструкции / программа), stmt (ядро / host),
  func, module (хелперы / конверсии / секции), driver.
* **Без дублирования.** Общие предикаты (`is_ident_kind`, `name_eq`,
  `is_lit`, `tok_kind`, `tok_val`) и таблицы — единственный экземпляр. Если
  логика повторяется в двух частях, вынесите её в общую часть, а не
  копируйте.
* **Порядок частей — только для читаемости.** Функции в Latent можно
  вызывать до объявления: `scan_signatures` и `tc_register` собирают все
  сигнатуры заранее. Поэтому сортировка имён не влияет на семантику; новый
  файл получает номер по своей полосе (00–09 ABI, 10–19 буфер, 20–29 lexer,
  30–34 syntax, 35–39 class/enum/lambda, 40–49 emit, 45–49 typecheck,
  50–59 stmt, 60–69 func, 70–79 module, 90 driver).

## 6. Имена и комментарии

* Идентификаторы — **английский**, комментарии и документация — **русский**,
  UTF-8 без BOM.
* Префиксы:

| Префикс | Смысл |
|---|---|
| `emit_`, `ev_` | эмиссия байтов/инструкций (эффект) |
| `b*` (`bput`, `bleb`, `bcopy`, `binit`) | операции с байтовым буфером (эффект) |
| `add_`, `set_`, `scan_`, `register_` | запись в таблицу/состояние (эффект) |
| `find_`, `get_`, `is_`, `*_len`, `*_tp` | чтение (запрос) |
| `st_` | инструкция (statement) |
| `tc_` | тайп-чекер |
| `level_`, `parse_` | разбор выражения |
| `helper_` | тело рантайм-хелпера в выходном модуле |

* Комментарий объясняет **почему** и **формат** (stride, раскладку, порядок
  байтов), а не пересказывает код.
* Для каждого нового слота памяти — комментарий в `00_abi.lat` с адресом,
  размером и смыслом.

## 7. Где императивность неизбежна и почему

Полностью чистый код в этом подмножестве невозможен; ниже — места, где
императивность **разрешена и ожидаема**, и как её изолировать.

1. **Линейная память — единственная структура данных.** Нет массивов-значений,
   структур и сборщика мусора: таблицы — это `store32`/`load32` по
   фиксированным адресам. Изоляция: доступ только через аксессоры
   `00_abi.lat`, остальные части не знают числовых адресов.
2. **Буферы и LEB128.** `bput`/`bleb`/`bcopy` обязаны мутировать длину и
   байты; это append-only структура. Изоляция: `10_buffer.lat`, никакой
   другой части не нужно знать про `[len][bytes]`.
3. **Эмиссия WASM.** Порядок байтов — это семантика модуля. Изоляция:
   `40*_emit_*` и `70*_module_*`; эффект виден по имени.
4. **Курсор парсера.** `get(0, PC)`/`next_token()` — неизбежное состояние
   разбора. Изоляция: `30_syntax` и `45a..45d_tc_*`; запросы `tok_kind`/`tok_val` — pure.
5. **Регистрационные проходы.** `scan_classes`, `scan_enums`, `scan_lambdas`
   заполняют таблицы; они императивны по определению, но не должны вызываться
   повторно без сброса счётчиков (это делает драйвер).
6. **Производительность и bootstrap-ограничения.** Компилятор компилирует
   сам себя; лишние абстракции (лямбды, косвенные вызовы, обобщения) могут
   замедлить или сломать фиксированную точку. Предпочитайте прямые вызовы и
   явные параметры.

## 8. Соотношение с текущим кодом

`shc.lat` — процедурный компилятор: токены в параллельных массивах, таблицы
в линейной памяти, проходы `tokenize → scan_* → tc_* → compile_* →
build_module`. Переписывать его в «чистый» стиль не нужно и опасно для
фиксированной точки.

Что делаем практически:

1. **Границы, а не революция.** Новые функции — чистые запросы или явные
   эффекты; старые приводим по мере декомпозиции.
2. **Разделяем смешанные функции.** Пример: вместо `find_or_add_str`
   используем `find_str` + `add_str` (уже так).
3. **Именуем стоки.** `emit_*` пишет только в текущий буфер; `helper_*`
   пишет тело хелпера; `build_module` пишет секции.
4. **Документируем слоты.** Любая новая таблица — строка в карте `00_abi` и
   комментарий с раскладкой.
5. **Проверяем фиксированную точку после каждого шага.** Любой рефакторинг,
   меняющий эмиссию, обязан пройти `node selfhost/build.mjs`,
   `node selfhost/bootstrap.mjs` (`FIXED POINT`) и весь selfhost-набор.

## 9. Чек-лист code review

- [ ] Файл ≤ 300 строк; функция, как правило, ≤ 50 строк.
- [ ] Имя функции соответствует категории (`find_`/`get_`/`is_` — запрос;
      `emit_`/`add_`/`set_`/`scan_` — эффект).
- [ ] Чистые запросы не пишут в память и не двигают курсор.
- [ ] Нет числовых адресов вне `00_abi.lat`; новый слот задокументирован
      (адрес, размер, stride, владелец).
- [ ] Нет скрытых глобальных мутаций: состояние — только через `get`/`set`
      и именованные таблицы.
- [ ] Ошибки идут в `status`/`ERRB`, не глотаются; `err()` проверяется
      вызывающим/драйвером.
- [ ] Нет дублирования логики: общие предикаты и таблицы переиспользуются.
- [ ] Порядок эмиссии не изменён без дифференциального теста и проверки
      `stage2 === stage3`.
- [ ] Новые тесты — дифференциальные (oracle vs stage1 vs stage2) и/или
      атомарные; покрытие не падает.
- [ ] Комментарии — по-русски, идентификаторы — по-английски, UTF-8 без BOM.
- [ ] Нет мёртвого кода и неиспользуемых слотов.
- [ ] `node selfhost/build.mjs && node selfhost/bootstrap.mjs` — `FIXED POINT`.
- [ ] `node --test "selfhost/test/*.test.mjs"` — зелёный.
- [ ] `node tooling/selfhost-coverage/run.mjs --min 90` — покрытие функций ≥ 90%.

## 10. Метрики и команды

```bash
# сборка и фиксированная точка
node selfhost/build.mjs
node selfhost/bootstrap.mjs          # ожидается FIXED POINT: stage2 === stage3

# регресс
node --test "selfhost/test/*.test.mjs"

# покрытие функций (и, при --lines, приблизительное покрытие инструкций)
node tooling/selfhost-coverage/run.mjs --min 90
node tooling/selfhost-coverage/run.mjs --lines
```

Отчёт: `tooling/selfhost-coverage/coverage.md` + `coverage.json`.
Методика и ограничения — `tooling/selfhost-coverage/README.md`.
План декомпозиции — `tooling/selfhost-coverage/decomposition-plan.md`.
