# Философия языка

Latent спроектирован как **маленький язык с большим рантаймом-контрактом**:
сложность должна жить в хосте (браузер, Node.js), а в языке — только то, что
можно объяснить и скомпилировать без магии.

## Принципы

### 1. Один язык — два движка, честные ошибки

Движок №1 (JS-интерпретатор) исполняет большую часть языка, включая host-фичи:
каналы, goroutines, тензоры, AI-примитивы. Чего он не умеет — например,
`enum`, битовых операторов и блочных комментариев — видно при запуске: это
ошибка движка №1, а не «магии». Движок №2 (Rust → WASM) компилирует
подмножество и для неподдерживаемой конструкции даёт **явную ошибку** с
названием конструкции, а не молчаливый no-op:

```text
Builtin 'channel' не поддерживается движком №2 (требует host-рантайма)
```

Такая ошибка относится **только к движку №2**. Для пользователя граница
прозрачна: playground исполняет host-фичи движком №1 и автоматически выбирает
движок (авто-фолбэк), а движок №2 — внутренний WASM-компилятор подмножества.
Тот же контракт позволяет одному и тому же исходнику быть учебным примером,
тестом компилятора и спецификацией одновременно. В документации у каждой
темы есть раздел «Ограничения движка №2».

### 2. Типы как помощь, а не барьер

Система типов — Hindley–Milner-подобная: вывод типов, обобщение функций,
унификация. Но язык не заставляет аннотировать всё: `int` и `float`
унифицируются между собой, массивы не требуют гомогенности элементов,
методы встроенных типов типизируются динамически. Строгая типизация
включается там, где она ловит ошибки: условия `if`/`while` обязаны быть
`bool`, вызовы — соответствовать арности.

### 3. AI — это грамматика

`ai_infer`, `ai_embed`, `ai_stream`, `stream_next`, `tensor`, `semantic`,
`matmul`, `cosine_similarity`, `agent`, `embedding`, `ai_generate!`,
`ai_contract` — ключевые слова и встроенные функции. Это **синтаксис языка**,
а не библиотека: примитивы разбираются парсером и доступны в браузерном
рантайме (движок №1) без бандлеров и SDK. Язык не делает вид, что
детерминированно исполняет модель: AI-вызов — это запрос к гейтвею (или mock),
и результат зависит от провайдера.

### 4. Тестируемость по умолчанию

В языке есть `test "имя" { ... }`, `assert`, `assert_eq`, `snapshot`,
декораторы `@forall` и `@ai_contract`. Идея: программа на Latent — это
одновременно код и его проверки. Тестовые блоки исполняются движком №1 после
`main`; `assert` падает с ошибкой исполнения.

### 5. WASM как единственная цель

Компилятор не прячет модель памяти: линейная память, bump-аллокатор, строки
`[длина u32 LE][UTF-8]`, массивы `[длина][элементы]`, классы как структуры с
фиксированными смещениями. Благодаря этому возможны низкоуровневые примитивы
`alloc`/`load8`/`store8`/`load32`/`store32`/`memcopy` и self-hosting.

### 6. Самодостаточность

Компилятор — один крейт Rust без зависимостей (`Cargo.toml` — только
`[package]` и `[lib]`) и без LLVM. В репозитории есть self-hosted компилятор
(`selfhost/`) с фиксированной точкой bootstrap: `stage2 === stage3`. При этом
**Rust не обязателен для пользователя**: bootstrap можно запускать без Rust —
из `selfhost/seed.wasm` (`node selfhost/bootstrap-wasm.mjs`), а Rust нужен
только для однократного обновления seed. Подробнее —
[specs/selfhost](../specs/selfhost.md).

## Компромиссы и статус

| Решение | Что получаем | Статус |
|---|---|---|
| Нет модулей/импортов | Простой парсер, один файл — одна программа | **Остаётся** (дорожная карта: modules + chunks; ленивые чанки для WASM-бандлов уже есть) |
| Нет GC, bump-аллокатор | Предсказуемость, минимум рантайма | **Остаётся** (дорожная карта) |
| Классы без наследования | Простая модель объектов | **Остаётся** |
| `int`/`float` унифицируются | Меньше аннотаций | **Остаётся**; частично компенсируется тайп-чекером |
| Динамические массивы | Удобство | **Остаётся** |
| Host-граница для AI/каналов | Ясный контракт движков | **Устранена для пользователя**: браузерный рантайм (движок №1) исполняет host-фичи, playground автоматически выбирает движок; движок №2 остаётся WASM-компилятором подмножества (внутренняя реализация) |
| Собственный кодоген | Маленький, понятный, self-hosted | **Устранена зависимость от Rust**: self-hosted bootstrap без Rust (`seed.wasm`); Rust — только для однократного обновления seed |
| Оптимизаций почти нет | Простой кодоген, быстрый для небольших программ | **Остаётся** (дорожная карта) |

### Что уже снято

Два ограничения, которые раньше были видны пользователю, больше не являются
компромиссами:

- **Host-фичи в браузере.** В обычном Run больше нет ошибок «требует
  host-рантайма»: playground исполняет каналы, `spawn`/`select`, AI-примитивы,
  тензоры и контракты через движок №1 и автоматически выбирает движок
  (авто-фолбэк). Упомянутая выше ошибка остаётся только у движка №2 — это
  внутренний WASM-компилятор подмножества. Подробнее —
  [tooling/web-ide](../tooling/web-ide.md).
- **Зависимость от Rust.** Компилятор Latent запускается без Rust: self-hosted
  bootstrap стартует с `seed.wasm`, собирает stage, проверяет фиксированную
  точку и предоставляет CLI `compile/check/run/version`; Rust нужен только для
  однократного обновления seed. Подробнее —
  [specs/selfhost](../specs/selfhost.md).

### Дорожная карта

- **Модули и чанки.** Модули/импорты (один файл — одна программа сейчас);
  ленивые чанки для WASM-бандлов уже работают в playground: динамический
  импорт + `manualChunks` (`engine2` / `ai` / `editor` / `examples` / `core`),
  production-сборка на Vite — см. [tooling/web-ide](../tooling/web-ide.md).
- **Память.** GC/освобождение либо арена-стратегии поверх bump-аллокатора.
- **Оптимизации кодогена.** Базовые оптимизации WASM без потери self-hosting.
- **Веб и фронтенд.** Новые сценарии использования Latent в браузере —
  [guide/web-and-frontend](../guide/web-and-frontend.md).

## Стиль кода

В репозитории принято:

- **идентификаторы — английские** (`total`, `compute`, `Account`);
- **комментарии и документация — русские**;
- UTF-8 без BOM; отступ — 4 пробела; точка с запятой обязательна после
  инструкций;
- имена типов — `CamelCase`, функции и переменные — `snake_case`;
- `main` возвращает `int` (код возврата).
