# Сравнение с Rust, TypeScript и Go

Latent — не замена этим языкам. Это маленький исследовательский язык; его
разумно сравнивать по **механизмам**, а не по зрелости. Ниже — честная
таблица: где Latent действительно отличается, а где проигрывает.

## Коротко

| Критерий | Latent | Rust | TypeScript | Go |
|---|---|---|---|---|
| Зрелость | экспериментальный, 0.1 | production | production | production |
| Экосистема/пакеты | нет модулей | cargo/crates.io | npm | go modules |
| Типизация | HM-вывод + аннотации, динамические послабления | строгая, trait-based | структурная, стирается при компиляции | номинальная, интерфейсы |
| Исполнение | WASM (свой кодоген) или JS-интерпретатор | нативный код / WASM через LLVM | JS-рантайм | нативный код |
| Память | линейная память WASM, bump-аллокатор, без GC | ownership/borrow checker | GC движка | GC |
| Конкурентность | CSP: spawn/channel/select (движок №1) | потоки, async (tokio) | event loop, Worker | goroutines/channels |
| ООП | классы без наследования | struct + trait | class/interface | struct + interface |
| Дженерики | ограниченно, встроенные типы | полноценные | полноценные | с 1.18 |
| Тесты | синтаксис языка (`test`, `assert`) | `#[test]` + cargo | фреймворки | `testing` |
| AI-примитивы | встроены как синтаксис | библиотеки | библиотеки | библиотеки |

## Типы и вывод

**Latent.** Вывод типов в духе Hindley–Milner: функции обобщаются, вызовы
унифицируются. Аннотации необязательны. `int` и `float` унифицируются между
собой, из-за чего числа проверяются мягче, чем в Rust:

```latent
fn add(a: int, b: int) -> int {
    return a + b;
}

fn main() -> int {
    let x = 40;
    let y: int = 2;
    print(add(x, y));
    return add(x, y);
}
```

**Rust.** Строгая номинальная типизация, trait-объекты, заимствование.
Никаких неявных преобразований чисел.

**TypeScript.** Структурная типизация; типы стираются при сборке в JS, поэтому
гарантии заканчиваются на границе рантайма.

**Go.** Номинальная типизация, интерфейсы реализуются неявно, обобщения есть с
1.18, но без «умного» вывода в стиле HM.

## Память

| | Latent | Rust | TypeScript | Go |
|---|---|---|---|---|
| Модель | линейная память WASM | стек/куча, ownership | куча + GC | куча + GC |
| Освобождение | нет (bump-аллокатор) | детерминированное (Drop) | GC | GC |
| Проверка границ | нет | да (срезы) | да (массивы JS) | да |
| Null | `null` = 0 | `Option<T>` | `null`/`undefined` | nil |

```latent
fn main() -> int {
    // Строки и массивы живут в линейной памяти [длина][данные].
    let name = "latent";
    let sizes = [1, 2, 3];
    print(name.length + sizes.length);
    return 0;
}
```

Отсутствие освобождения — осознанный компромисс Latent: долгоживущая программа
постепенно расходует память. Для учебных и коротких программ этого достаточно.

## Конкурентность

**Latent (движок №1)** — CSP в духе Go: горутины `spawn`, каналы `channel()`,
`select`, кооперативный `yield`, отправка `ch <- v` и приём `<-ch`:

```latent
// Не компилируется движком №2: каналы требуют host-рантайма.
fn worker(ch, n) {
    ch.send(n * n);
}

fn main() -> int {
    let ch = channel();
    spawn worker(ch, 7);
    let result = ch.recv();
    print("result:", result);
    return result;
}
```

**Rust** — потоки и async/await (обычно через tokio), без встроенного
планировщика. **TypeScript** — один поток событий + `Promise`, параллелизм
только через Worker/процессы. **Go** — ближайший аналог: goroutines и
channels, но с настоящим планировщиком и без host-границы.

Движок №2 Latent каналы не поддерживает: `channel`, `ch.send`, `ch <- v`,
`<-ch` дают явную ошибку. `spawn` и `select` в нём компилируются, но выполняются
последовательно (см. [concurrency](../guide/concurrency.md)).

## ООП и данные

**Latent.** Класс — это поля и методы; конструктор называется `init`; полиморфизма
подтипов нет. Sum-типы — `enum` + `match`, как в Rust:

```latent
enum Shape { Circle(int), Rect(int, int) }

fn area(s: Shape) -> int {
    return match s {
        case Circle(r): 3 * r * r,
        case Rect(w, h): w * h,
    };
}

fn main() -> int {
    return area(Rect(3, 4));
}
```

**Rust** — `struct`/`enum` + `trait` (композиция вместо наследования).
**TypeScript** — `class`, наследование, интерфейсы, но типы стираются.
**Go** — `struct` + методы + `interface`, без наследования; enum как
пользовательский тип не поддержан на уровне языка (константы + iota).

## Сборка и таргет

| | Latent | Rust | TypeScript | Go |
|---|---|---|---|---|
| Цель | WASM (`wasm32`) | native, WASM | JS | native |
| Бэкенд | собственный кодоген WASM | LLVM | tsc/babel | собственный |
| Время сборки | миллисекунды для небольших программ | зависит от проекта | быстро | быстро |
| Оптимизации | почти нет | агрессивные | JIT | агрессивные |

## AI-примитивы

**Latent.** `ai_infer("gpt-4", "промпт")`, `ai_embed(text)`,
`ai_stream`/`stream_next`, `tensor`/`matmul`/`cosine_similarity`,
`semantic(...)` и `ai_generate!("...")` — часть языка. В движке №1 они
обращаются к AI-гейтвею и имеют mock-режим; в движке №2 — явная ошибка.

**Rust/TypeScript/Go.** AI — это библиотеки и HTTP-клиенты; язык о них ничего
не знает. Плюс Latent здесь в синтаксисе и едином контракте, минус — в
отсутствии экосистемы и в том, что без хоста эти примитивы не работают.

## Когда Latent уместен

- эксперименты с языками и компиляторами;
- обучение: маленький полный тулчейн;
- браузерные playground-сценарии;
- генерация и проверка кода AI-агентами (машинно-читаемая документация, MCP).

## Когда Latent неуместен

- production-сервисы и библиотеки;
- программы, которым нужны модули, пакеты и экосистема;
- долгоживущие процессы с большим объёмом данных (нет GC);
- задачи, где нужна производительность уровня Rust;
- что-либо, где требуется совместимость с существующим кодом.
