# Self-hosted компилятор Latent

Компилятор Latent→WASM, написанный на самом Latent (подмножество языка), без
опоры на Rust-реализацию. Цель — bootstrap (фиксированная точка): компилятор,
собранный собой, побайтово совпадает с собой.

## Статус

* **Фиксированная точка достигнута.** `stage2 === stage3` — компилятор,
  собранный собой, воспроизводит себя побайтово (проверяется `bootstrap.mjs`
  и тестом `bootstrap.test.mjs`).
* `shc.lat` корректно компилирует подмножество языка: рекурсия, циклы
  (в т.ч. `for-in` по массивам), строки (конкатенация, равенство,
  индексация, длина, escape-последовательности), массивы/индексация/
  `push`/`pop`, преобразования `str`/`int`/`float`/`to_str`/`to_int`,
  `assert`/`assert_eq`, короткое замыкание `&&`/`||`, работа с линейной
  памятью, классы/enum/замыкания, `match` (числа, строки, конструкторы),
  float.
* **Регресс-набор: 166 тестов** (`selfhost/test/`, `node --test`):
  85 исходных + 56 дифференциальных в `parity.test.mjs` + 25 Rust-free
  в `bootstrap-wasm.test.mjs`.
* **Rust не обязателен.** В репозитории лежит `selfhost/seed.wasm` — уже
  собранный компилятор (паритет 64/65); `node selfhost/bootstrap-wasm.mjs`
  строит из него `stage-sh-1 → stage-sh-2 → stage-sh-3` и проверяет
  фиксированную точку **без latentc/cargo**. Этим же seed можно пользоваться
  как обычным компилятором: `node selfhost/wasm-compiler.mjs compile|check|run`.
  Rust нужен только чтобы один раз восстановить seed, если он утерян
  (см. «Компиляция без Rust»).
* **Матрица паритета** (`latent-work/gap-matrix.mjs`): **64/65 кейсов
  совпадают** с Rust-эталоном, включая 11 кейсов «все три компилятора дают
  ошибку». Единственное оставшееся расхождение — `float`-литералы, где
  selfhost **сильнее** эталона (см. ниже).
* Текст ошибок у stage2 теперь **совпадает** с stage1 (исправлен баг
  типизации строковых параметров, из-за которого само-скомпилированный
  компилятор читал буфер сообщения как массив 4-байтовых ячеек).

## Паритет с Rust-компилятором

Self-hosted компилятор следует за функциональностью `latentc` (Rust)
инкрементально; каждое расширение проверяется дифференциально против
oracle и обязано сохранять фиксированную точку.

Паритет = «все три компилятора успешно собрали программу и `main()` вернул
одно и то же» **или** «все три отказались компилировать». Второй случай
важен для host-конструкций: Rust-эталон тоже не умеет их компилировать, но
даёт осмысленную ошибку — selfhost обязан дать такую же по смыслу (и с тем
же именем конструкции).

| Область | Статус |
|---|---|
| let/if/else/while/for/return | есть |
| арифметика/сравнения/биты | есть |
| `&&`/`\|\|` (короткое замыкание) | есть |
| массивы: литерал, `[]`, `.length`, `push`, `pop`, `len` | есть |
| строки: `+`, `==`/`!=`, `s[i]`, `len` | есть |
| escape-строки `\n` `\t` `\\` `\"` | есть |
| `str`/`int`/`float`/`to_str`/`to_int` | есть (по статическому типу получателя) |
| `print(a, b, …)` | есть: конверсия int/float/строка, отдельная строка на аргумент |
| `null` | есть (`0`, как в эталоне) |
| `assert`/`assert_eq` | есть |
| классы: `class`, поля, `this`, методы, `new` | есть |
| enum: варианты (теги + полезная нагрузка) | есть |
| `match`/`case` (числа, строки, `_`/`default`, конструкторы) | есть |
| замыкания: `fn(x) => expr`, `fn(x) { ... }`, захваты, `call_indirect` | есть |
| тайп-чек: аннотации, возвраты, арность, условия, присваивания | есть |
| обработка ошибок: текст ошибки вместо WASM (отрицательный результат) | есть |
| **`spawn { … }` / `spawn expr;`** | **есть** — тело исполняется последовательно (inline), как в эталоне |
| **`yield;`** | **есть** — no-op |
| **`async fn`** | **есть** — флаг игнорируется, сигнатура как у обычной функции |
| **`await expr`** | **есть** — passthrough значения |
| **`select`-выражение** | **есть** — первая ветка (переменная = 0), иначе `default`, иначе `0` |
| **`select`-инструкция** | **есть** — тело первой ветки, иначе `default`; выражения каналов не вычисляются |
| **`test "name" { … }` / `test("name") { … }`** | **есть** — top-level не эмитится, внутри функции исполняется |
| **`channel()` / `channel<T>()`** | **ошибка host-рантайма** с именем builtin’а |
| **`tensor`/`semantic`/`matmul`/`cosine_similarity`/`dot`/`magnitude`/`zeros`/`ones`/`snapshot`/`ai_contract`/`enforce_contract`/`ai_infer`/`ai_embed`/`ai_stream`/`stream_next`** | **ошибка host-рантайма** с именем builtin’а |
| **`ai_generate!("…")`** | **ошибка host-рантайма** (движок №1) |
| **`ch <- v` / `<- ch` / `ch.send` / `ch.recv`** | **ошибка host-рантайма** (движок №1/№2) |
| **неизвестный метод** (`arr.len()`, `"x".upper()`, …) | **ошибка host-рантайма** с именем метода |
| **`for (let c in "abc")`** | **ошибка типов** (как в эталоне), а не побайтовая итерация |
| **top-level `let`** | при использовании — **`undefined variable` с именем** (как `Undefined variable` эталона), а не invalid WASM; неиспользуемый — компилируется |
| **`undefined variable` / `undefined function`** | **ошибка с именем** (не invalid WASM) |
| float-литералы `1.25`, `1e3`, `2.5e1`, `1250e-1`, `+ - * /`, сравнения, `int(float)` | есть |
| float-возврат `fn f() -> float`, f64 в выражениях | есть |
| float-локальные `let x: float` / `let x = 2.5` (f64-valtype) | есть |
| `sqrt(x)`, `float(x)` | есть (включая `float("42")` — парсинг строки) |
| `str(float)` (6 знаков, `f64_to_str`) | есть |
| строковые параметры `fn f(s: string)` — `s[i]` как байт строки | есть |
| смешанная арифметика `int ⊕ float` (повышение int→f64) | есть (сверх эталона) |
| вложенные блочные комментарии `/* a /* b */ c */` | есть |
| float-параметры `fn f(r: float)` | нет (в эталоне тоже невалидно) |
| `@`-декораторы (`@test`, `@forall`, …) | нет (см. «Остаточные расхождения») |

> **Float.** Реализован **без кодирования битов IEEE754**: значение литерала
> собирается как f64-арифметика `mant / 10^k * 10^exp` (i32→f64 через
> `f64.convert_i32_s`), что не требует 64-битной мантиссы в i32-компиляторе.
> Целочисленно-значные литералы (`2.0`, `1e3`, `2.5e1`, `1250e-1`)
> сворачиваются в int, как в oracle (наблюдаемо через `str(2.0)` → `"2"`).
>
> **Selfhost — надмножество эталона по float.** Проверенные живьём случаи
> `int(2.5 * 2.0)`, `int(sqrt(16.0))`, `let x: float = 2.5`, `str(2.5)`,
> `let x = 1e-3; x * 1000.0`, смешанные `2 < 2.5` / `1 + 0.5` дают **валидный
> WASM и верный результат** в selfhost, тогда как `latentc` на них падает с
> невалидным WASM или ошибкой типов.

## Host-конструкции: что именно делает selfhost

Rust-эталон («движок №2») не имеет host-рантайма, но часть конструкций он
компилирует в суррогат, а часть — отвергает. Selfhost повторяет **наблюдаемое
поведение эталона**, а не гипотетическую семантику:

* `spawn { ... }` / `spawn expr;` — тела выполняются **последовательно** в
  текущей функции; `return` внутри `spawn` возвращает из объемлющей функции;
  результат выражения-формы отбрасывается (`DROP`).
* `yield;` — no-op (`;` обязательна, как в парсере эталона).
* `async fn` — флаг `is_async` не влияет на сигнатуру/код; Promise не
  материализуется.
* `await expr` — прозрачное разворачивание: значение операнда как есть.
* `select { case v <- ch: … }` — выражения каналов **не компилируются**
  (эмитятся и откатываются), `v` связывается с `0`, исполняется тело
  **первой** ветки; `default` — только если веток нет; пустой `select` в
  позиции выражения даёт `0`.
* `test "name" { … }` — на верхнем уровне парсится и **не эмитится** (раннера
  нет); внутри функции тело исполняется как обычный блок.
* `channel()`, `channel<T>()`, `tensor(…)`, `ai_*`, `ch <- v`, `<-ch`,
  `ch.send`/`ch.recv`, неизвестные методы — **ошибка кодогена** с именем
  конструкции, текст в формате selfhost:
  `error: builtin 'channel' requires host runtime (engine #2)`,
  `error: channel operations require host runtime (engine #1)`,
  `error: AI primitives require host runtime (engine #1)`.
* `ai_generate!("prompt")` — ошибка «AI требует host-рантайма движка №1».

## Обработка ошибок

Ошибки делятся на два прохода:

1. **Тайп-чек** (`45_typecheck.lat`) — пишет `[len u32][utf8]` в `ERRB` и
   выставляет `status`; кодоген не запускается.
2. **Кодоген** — ошибки с именем (`err_named`: `undefined variable: g`,
   `undefined function: nosuch`, `builtin 'tensor' …`, `method 'len' …`)
   тоже пишутся в `ERRB`. Раньше кодоген продолжал работу и отдавал
   невалидный WASM; теперь драйвер проверяет `status` **после** эмиссии и
   возвращает отрицательную длину с текстом ошибки — как тайп-чек.

`main()` компилятора возвращает длину выходного WASM — либо **отрицательную**
величину при ошибке компиляции: тогда по адресу 65536+4 лежит `len` байт
UTF-8 текста ошибки (`[len u32 LE][utf8]`), который хост читает как сообщение.

**Регресс stage2 (исправлен).** Текст ошибок само-скомпилированного
компилятора читался как мусор (`erni cn oaysc …`). Причина: в
`compile_fn` все параметры объявлялись локальными типа `int`, хотя аннотация
`fn tcerr_msg(s: string)` читалась и отбрасывалась. Поэтому `s[i]` внутри
`tcerr_msg` компилировался как индекс **массива** (`i32.load` по `4+4*i`) и
брал каждый 4-й байт сообщения. Теперь аннотация параметра задаёт тип
локальной: `string → T_STR`, остальные — `int`; `s[i]` для строкового
параметра — `str_char_at`. Дифференциальный тест `parity.test.mjs`
дополнительно требует, чтобы тексты ошибок stage1 и stage2 совпадали
посимвольно.

## Структура исходников (SOLID, ≤300 строк на часть)

Язык компилируется одним файлом и не имеет системы модулей, поэтому `shc.lat`
собирается из ответственностно-разделённых частей через детерминированную
линковку (`build.mjs`). Каждая часть отвечает за одну обязанность (SRP), ни
один файл не превышает 300 строк (максимум — 278); стиль — функционально-чистые
границы, состояние только через документированные слоты линейной памяти
(см. [`docs/docs/specs/selfhost-style.md`](../docs/docs/specs/selfhost-style.md)).

| Часть | Обязанность |
|---|---|
| `src/00_abi.lat` | Карта линейной памяти, доступ к слотам состояния, float-опкоды. |
| `src/10_buffer.lat` | Байтовые буферы `[len u32][bytes]`, кодирование LEB128. |
| `src/20_lexer.lat` | Исходник → параллельные массивы токенов (числа/экспоненты, строки с escape, вложенные комментарии, `<-`). |
| `src/30_syntax.lat` | Курсор токенов, локальные, таблицы функций и строк (escape-aware `add_str`). |
| `src/35_class.lat` | Регистрация классов (поля/методы) и enum-вариантов. |
| `src/36_lambda.lat` | Регистрация лямбд/захватов; компиляция тел, closure/env. |
| `src/40a_expr_emit.lat` | «Словарь» эмиттера: опкоды/LEB в буфер функции, встроенные вызовы (память, строки, конверсии, assert, print). |
| `src/40b_expr_values.lat` | Host-builtin'ы с ошибкой по имени, вызов по индексу, float-литералы без IEEE754-битов. |
| `src/40c_expr_primary.lat` | Первичные выражения: литералы, идентификаторы, `await`, `null`, лямбда-литерал, косвенный вызов. |
| `src/40d_expr_objects.lat` | `match`, `select`-выражение, создание объекта класса (`new`/`init`). |
| `src/40e_expr_postfix.lat` | Индексация, `.length`, поля классов, вызовы методов (push/pop/length/to_str/to_int). |
| `src/40f_expr_assign.lat` | Унарные выражения, литерал массива, присваивание, вход в Pratt-парсер. |
| `src/40g_expr_operators.lat` | Бинарные уровни Pratt: `&&`/`\|\|`, сравнения, битовые, сдвиги, арифметика i32/f64, конкатенация строк. |
| `src/45a_tc_core.lat` | Тайп-чекер: ядро — теги типов, буфер ошибок `ERRB`, курсор, таблица переменных, аннотации. |
| `src/45b_tc_expr.lat` | Тайп-чекер: вывод типов выражений (литералы, вызовы, постфикс, лямбды, бинарные уровни). |
| `src/45c_tc_flow.lat` | Тайп-чекер: `match` и инструкции (let/return/if/while/for/spawn/yield/test/select). |
| `src/45d_tc_program.lat` | Тайп-чекер: регистрация функций, верхнеуровневый проход, проверка тела функции. |
| `src/50_stmt.lat` | Эмиссия инструкций (let/if/while/for/return/assign/spawn/yield/select/test); `err_named`. |
| `src/60_func.lat` | Сборка одного тела функции (локальные, типы параметров/результата). |
| `src/70a_module_helpers.lat` | Байткод хелперов памяти/строк: alloc, memcopy, str_concat, str_eq, str_char_at. |
| `src/70b_module_convert.lat` | Байткод конверсий: i32_to_str, str_to_i32, f64_to_str, f64-константы. |
| `src/70c_module_sections.lat` | Сборка секций WASM-модуля (type/import/func/table/memory/global/export/element/code/data). |
| `src/90_driver.lat` | Точка входа: полный проход компиляции, ошибки → отрицательная длина. |

`shc.lat` (~166 KB) генерируется — редактировать нужно части, затем пересобрать:

```sh
node selfhost/build.mjs        # src/*.lat -> shc.lat
```

> Контроль размера: части читаются из `src/`, `shc.lat` растёт вместе с
> компилятором. Входной диапазон — выше 3 145 728 до таблиц классов
> (3 407 872) — запас ~100 KB; при дальнейшем росте нужно сдвигать области
> (`00_abi.lat`) и `alloc(...)` в драйвере.

## Покрытие тестами

Функциональное покрытие self-hosted компилятора измеряется инструментально:
`tooling/selfhost-coverage` вставляет счётчики в начало каждой функции,
собирает инструментированный `shc.lat` и прогоняет корпус (тесты, примеры,
probe- и fuzz-программы).

```sh
node tooling/selfhost-coverage/run.mjs --min 90
```

Актуальный отчёт (`tooling/selfhost-coverage/coverage.md`):
**функции 93.52% (361 из 386), строки ~95.35%, порог PASS**. Непокрытые
функции — в основном геттеры адресов из `00_abi.lat` и редкие ветви эмиттера;
они перечислены в отчёте.

## ABI компилятора

| Адрес | Назначение |
|---|---|
| 3145728 | входной исходник: `[len u32 LE][utf8 bytes]` (область 128K+, растёт вверх до таблиц классов) |
| 65536 | выходной WASM: `[len u32 LE][bytes]` после вызова `main()` |

> Входной исходник вынесен в отдельную высокую область, а не прижат к 32768:
> по мере роста `shc.lat` его хвост перекрывал `OUTB`, который `binit()`
> зануляет на старте, — это молча портило последние токены (например, `FNLEN`
> превращался в `F`). Хост обязан нарастить память до адреса `INPUT_ADDR`
> перед записью исходника (`memory.grow`), так как компилятор растит её лишь
> в `main()`.

## Запуск

```sh
cargo build --bin latentc
node selfhost/build.mjs        # пересобрать shc.lat из частей
node selfhost/bootstrap.mjs    # stage1 -> stage2 -> stage3, фиксированная точка
```

`bootstrap.mjs` выполняет цепочку:

1. `latentc` (Rust) собирает `selfhost/shc.lat` → `stage1.wasm`;
2. `stage1.wasm` компилирует `selfhost/shc.lat` → `stage2.wasm` (self-compiled);
3. `stage2.wasm` компилирует `selfhost/shc.lat` → `stage3.wasm`;
4. проверяется `stage2 == stage3` (фиксированная точка).

## Компиляция без Rust

Rust нужен только для **первой** сборки компилятора из исходника. В
репозитории уже лежит результат такой сборки — `selfhost/seed.wasm`:
самохостящийся компилятор Latent→WASM (тот же `shc.lat`, паритет 64/65).
Дальше `cargo`/`latentc` не участвуют: seed компилирует `shc.lat`, полученный
компилятор компилирует `shc.lat` ещё раз, и байты обязаны совпасть.

```text
seed.wasm        -> shc.lat -> stage-sh-1.wasm   (stage1')
stage-sh-1.wasm  -> shc.lat -> stage-sh-2.wasm   (stage2')
stage-sh-2.wasm  -> shc.lat -> stage-sh-3.wasm   (stage3')

проверка: stage-sh-2 === stage-sh-3              (FIXED POINT, stage2' === stage3')
```

```sh
node selfhost/build.mjs            # src/*.lat -> shc.lat (только Node)
node selfhost/bootstrap-wasm.mjs   # seed -> stage1' -> stage2' -> stage3'; FIXED POINT
```

* `seed.wasm` + `seed.json` коммитятся; `stage-sh-*.wasm` — артефакты сборки,
  покрыты `.gitignore` (`selfhost/stage*.wasm`) и не пересекаются с
  `stage1/2/3.wasm` Rust-цепочки.
* `bootstrap-wasm.mjs` не запускает `latentc` и не читает `target/`; ABI —
  вход по адресу `3145728` (`[len u32][utf8]`), выход по `65536`
  (`[len u32][wasm]`), отрицательный `ret` — текст ошибки (см. «ABI
  компилятора»).
* `--no-write` — посчитать цепочку, но не писать stage-файлы;
  `--verify-seed` — сверить `seed.wasm` с `seed.json` и `shc.lat`.

### CLI без Rust

Seed — обычный компилятор, поэтому Latent можно собирать и запускать вообще без
Rust:

```sh
node selfhost/wasm-compiler.mjs compile hello.lat            # -> hello.wasm
node selfhost/wasm-compiler.mjs compile hello.lat out.wasm
node selfhost/wasm-compiler.mjs check hello.lat              # ошибка -> код 1 + текст
node selfhost/wasm-compiler.mjs run hello.lat                # печать print(), затем main()
node selfhost/wasm-compiler.mjs version                      # seed: версия, sha256, сверка
node selfhost/wasm-compiler.mjs version --compiler selfhost/stage-sh-2.wasm
```

* По умолчанию компилятор — `selfhost/seed.wasm`; переопределяется
  `--compiler <path>` или `LATENT_COMPILER=<path>`. Так можно проверить
  `stage-sh-2.wasm`: `version` покажет его sha256 и совпадение с seed.json.
* `compile` проверяет, что вышел валидный WASM, и пишет файл только при
  успешной компиляции; `check` ничего не пишет; `run` исполняет `main()`
  (код выхода — `main() & 0xFF`, импортируется только `env.print`).
* `version` печатает `compilerVersion`/`seedRevision` из `seed.json`, sha256
  компилятора, сверку с исходником `shc.lat` и состояние фиксированной точки
  (`stage-sh-2 === stage-sh-3`, если файлы есть).

### Как обновлять seed

Seed — **доверенная начальная точка**, а не «ещё одна сборка»: после правок
компилятора его нужно пересобрать и закоммитить вместе с `seed.json`.

```sh
# 1) пересобрать shc.lat из частей
node selfhost/build.mjs

# 2) убедиться, что цепочка замыкается на текущем seed
node selfhost/bootstrap-wasm.mjs

# 3) пересобрать seed из текущего shc.lat (только Node, без Rust)
node selfhost/bootstrap-wasm.mjs --refresh-seed
#    посмотреть diff, ничего не записывая:
node selfhost/bootstrap-wasm.mjs --refresh-seed --dry-run

# 4) проверить и закоммитить seed.wasm + seed.json
node selfhost/bootstrap-wasm.mjs --verify-seed
```

Что делает `--refresh-seed`:

1. строит `stage1' → stage2' → stage3'` **в памяти**;
2. отказывается что-либо писать, если `stage2' !== stage3'` (нет фиксированной
   точки) или если `stage2'` не воспроизводит себя побайтово;
3. печатает diff: размеры, sha256 до/после, число отличающихся байт и смещение
   первого отличия, а также изменившийся `shcSha256`;
4. записывает новый `seed.wasm` и обновляет `seed.json`: `seedSha256`,
   `seedBytes`, `shcSha256`, `shcBytes`, `updatedAt`, `verifiedAt`,
   `seedRevision` (растёт только когда меняются байты seed), `fixedPoint`.

После обновления seed `stage1' === seed` — это же проверяет тест
`bootstrap-wasm.test.mjs` (и `--verify-seed`).

> Аварийный Rust-путь `node selfhost/bootstrap.mjs --update-seed` пишет
> `seed.json` старого формата (без `compilerVersion`/`seedRevision`). После него
> выполните `node selfhost/bootstrap-wasm.mjs --refresh-seed`: байты seed не
> изменятся, а манифест обновится до схемы v2.

### Доверие и проверка

* `seed.json` — манифест происхождения: `seedSha256`/`seedBytes` (бинарник),
  `shcSha256`/`shcBytes` (исходник, из которого он собран), `compilerVersion`,
  `seedRevision`, даты.
* `bootstrap-wasm.mjs` на старте сверяет sha256/размер `seed.wasm` с
  `seed.json` и падает с кодом 2 при несовпадении (порча/подмена). Обойти
  проверку можно только явным `--refresh-seed` (он перезапишет seed) или
  `--no-verify`.
* Полная проверка вручную:

  ```sh
  node selfhost/bootstrap-wasm.mjs --verify-seed   # sha256 + размер + shc.lat
  sha256sum selfhost/seed.wasm                     # Linux/macOS
  certutil -hashfile selfhost\seed.wasm SHA256     # Windows
  ```

* Seed — бинарный артефакт, как `web-ide/compiler.wasm`: его обновление
  просматривается в diff'е (размер/sha256) и коммитится вместе с `seed.json`.
  Собирать/использовать seed можно офлайн, сеть не нужна.

### Ограничения

* Seed — это **последняя версия selfhost-компилятора**, а не весь язык:
  поддерживается подмножество из таблицы паритета (64/65). Host-конструкции
  (`channel`, `tensor`, `ai_*`, каналы) дают осмысленную ошибку «требует
  host-рантайма», float-параметры и `@`-декораторы не поддерживаются.
* Rust-free обновление работает, пока **старый seed умеет компилировать новый
  `shc.lat`**. Если изменение компилятора требует конструкции, которой в
  текущем seed ещё нет, «укусить себя за хвост» нельзя: один раз нужен Rust —
  `cargo build --bin latentc && node selfhost/bootstrap.mjs --update-seed`,
  дальше снова можно без Rust. Это классическая проблема bootstrap.
* `--refresh-seed` не «лечит» сломанный/подменённый seed: он собирает новый
  seed **из текущего**, поэтому исходный seed всё равно должен быть доверенным.
* Скомпилированной программе нужен хост, реализующий `env.print`; `run` в CLI
  делает это для консоли, для браузера/IDE — web-ide/движок №2.

## Побочный результат: примитивы памяти

Для селф-хостинга в Rust-реализацию (`latentc`) добавлены встроенные
небезопасные примитивы линейной памяти: `alloc(size)`, `load8(addr)`,
`store8(addr,v)`, `load32(addr)`, `store32(addr,v)`, `memcopy(dst,src,len)`.
См. `src/codegen/emit_call/direct.rs` (`compile_memory_builtin`).

> Примечание. Строковые литералы хранятся как `[len u32][utf8]`; оператор `+`
> над строками — конкатенация (не арифметика), поэтому байты литерала читаются
> по смещению `+4` после `memcopy`, а не через `s + 4`.

## Остаточные расхождения с эталоном (сознательные)

1. **float-литералы/float-выражения** — selfhost принимает и корректно
   исполняет то, что `latentc` компилирует в невалидный WASM или отвергает по
   типам (`int(2.5 * 2.0)`, `let x = 1e-3; x * 1000.0`, `print(2.5)` и т.п.).
   Это осознанное надмножество: математика на f64, а не кодирование битов.
2. **`fn f() -> unit { return; }`** — oracle выдаёт invalid WASM, selfhost
   выдаёт валидный модуль. Не «исправляется»: selfhost остаётся надмножеством.
3. **`await` не-Promise** (`await v()` для обычной `fn v() -> int`) — oracle
   требует `Promise<T>` и падает на типах; selfhost прозрачен. Надмножество.
4. **`@`-декораторы.** Лексер selfhost не выделяет `@` (пропускает символ).
   Поэтому `@forall("x") fn f()` даёт `undefined function: forall`, а
   `@test("t") fn f()` — вообще компилирует `f` (у oracle цель декоратора на
   top-level не регистрируется и вызов даёт `Unknown function: f`). Декораторы
   не используются ни в `shc.lat`, ни в тестах; семантика host-рантайма у них
   всё равно не реализована.
5. **`unit`-возврат** и **float-параметры** — см. пункты 1–2; параметры
   `r: float` в эталоне тоже дают invalid WASM, поэтому не поддерживаются.
6. **Арность builtin’ов.** Oracle местами молча игнорирует лишние/недостающие
   аргументы (`len()`, `assert()`, `alloc()`, `store8(a)`); selfhost строже и
   на пустых/неполных списках даёт `error: compilation failed`. Это не
   менялось: такие программы не встречаются в реальном коде.
7. **Мягкие ключевые слова как идентификаторы.** `spawn`/`yield`/`async`/
   `await`/`select`/`test`/`null` — полноценные ключевые слова; `fn test()`
   или `let spawn = 1` в selfhost не компилируются (oracle частично допускает
   их как soft-keywords).
8. **Точность float-литералов с длинной мантиссой.** Мантисса парсится в
   i32 (`mant`), поэтому литералы с более чем ~9 значащими цифрами или
   экстремальными экспонентами могут отличаться от f64-разбора эталона.
9. **Невалидный WASM по вине самого языка** (`x = 2.5` для `let x = 1`,
   `a[0] = 1.5`, `5.5 % 2.0`) — selfhost, как и oracle, не диагностирует эти
   дыры типовой системы; в отличие от oracle, часть из них (например,
   `5.5 % 2.0`) в selfhost даёт честную ошибку, а не невалидный модуль.
10. **Selfhost точнее типизирует результаты методов.** Oracle теряет
    строковый статический тип у результата вызова **метода**
    (`static_ty_of(Call с Field)` → Unknown), поэтому `print(n.to_str())`
    печатает адрес указателя, а `n.to_str()[i]` / `p.get()[i]` (метод,
    вернувший `string`) читают 4-байтовые ячейки как массив. Selfhost
    отслеживает тип результата (`T_STR`), поэтому печатает строку и
    индексирует **байты** строки. Это осознанное надмножество — как float:
    эталонные результаты в этих случаях наблюдаемо неверны
    (см. `parity.test.mjs`, блок «осознанные надмножества»).
