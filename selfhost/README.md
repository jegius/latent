# Self-hosted компилятор Latent

Компилятор Latent→WASM, написанный на самом Latent (подмножество языка), без
опоры на Rust-реализацию. Цель — bootstrap (фиксированная точка): компилятор,
собранный собой, побайтово совпадает с собой.

## Статус

* **Фиксированная точка достигнута.** `stage2 === stage3` — компилятор,
  собранный собой, воспроизводит себя побайтово.
* `shc.lat` корректно компилирует подмножество языка: рекурсия, циклы
  (в т.ч. `for-in` по массивам), строки (конкатенация, равенство,
  индексация, длина), массивы/индексация/`push`/`pop`, преобразования
  `str`/`int`/`to_str`/`to_int`, `assert`/`assert_eq`, короткое
  замыкание `&&`/`||`, работа с линейной памятью.
* Есть регресс-набор из 85 тестов (`selfhost/test/`, `node --test`).

## Паритет с Rust-компилятором

Self-hosted компилятор следует за функциональностью `latentc` (Rust)
инкрементально; каждое расширение проверяется дифференциально против
oracle и обязано сохранять фиксированную точку.

| Область                       | Статус |
|-------------------------------|--------|
| let/if/else/while/for/return  | есть |
| арифметика/сравнения/биты      | есть |
| `&&`/`\|\|` (короткое замыкание) | есть |
| массивы: литерал, `[]`, `.length`, `push`, `pop`, `len` | есть |
| строки: `+`, `==`/`!=`, `s[i]`, `len` | есть |
| `str`/`int`/`to_str`/`to_int` | есть |
| `assert`/`assert_eq`          | есть |
| классы: `class`, поля, `this`, методы, `new` | есть |
| enum: варианты (теги + полезная нагрузка) | есть |
| `match`/`case` (литералы, `_`/`default`, конструкторы) | есть |
| замыкания: `fn(x) => expr`, `fn(x) { ... }`, захваты, `call_indirect` | есть |
| тайп-чек: аннотации, возвраты, арность, условия, присваивания | есть |
| обработка ошибок: текст ошибки вместо WASM (отрицательный результат) | есть |
| `float`/`sqrt`/f64-арифметика | нет (нужен 64-битный decimal→IEEE754) |
| `float(...)`/`.toFloat`       | нет (зависит от float) |
| `spawn`/`select`/`await`/AI   | нет (host-рантайм) |

> Два оставшихся семейства вне self-hosting-подмножества:
> * `float` — требует кодировщика десятичной записи в 8 байт IEEE754, а он
>   нужен 64-битной арифметики (52-битная манттисса) в компиляторе,
>   написанном на i32-подмножестве; плюс параллельный список f64-valtype
>   для локальных. Отдельный подпроект.
> * `spawn`/`select`/`await`/AI — host-рантайм-примитивы, в самом Rust-эталоне
>   они заглушки/no-op.
>
> При этом **сам Rust-эталон частично несостоятелен на float**:
> `int(sqrt(16.0))` и `let x: float = 2.0` дают невалидный WASM в `latentc`.
> Для self-hosting (компилятор компилирует сам себя) достаточно
> целочисленного/указательного/строкового/замыканиевого подмножества, и
> фиксированная точка сохраняется на каждом шаге.

## Структура исходников (SOLID)

Язык компилируется одним файлом и не имеет системы модулей, поэтому `shc.lat`
собирается из ответственностно-разделённых частей через детерминированную
линковку (`build.mjs`). Каждая часть отвечает за одну обязанность (SRP):

| Часть              | Обязанность                                                     |
|--------------------|-----------------------------------------------------------------|
| `src/00_abi.lat`   | Карта линейной памяти, доступ к слотам состояния.              |
| `src/10_buffer.lat`| Байтовые буферы `[len u32][bytes]`, кодирование LEB128.        |
| `src/20_lexer.lat` | Исходник → параллельные массивы токенов.                       |
| `src/30_syntax.lat`| Курсор токенов, локальные, таблицы функций и строк.            |
| `src/35_class.lat` | Регистрация классов (поля/методы) и enum-вариантов.            |
| `src/36_lambda.lat`| Регистрация лямбд/захватов; компиляция тел, closure/env.       |
| `src/45_typecheck.lat`| Тайп-чекер: таблица типов, проверки, буфер ошибок.          |
| `src/40_emit_expr.lat`| Эмиссия выражений (Pratt), вызовов, строковых операций.    |
| `src/50_stmt.lat`  | Эмиссия инструкций (let/if/while/for/return/assign).           |
| `src/60_func.lat`  | Сборка одного тела функции.                                    |
| `src/70_module.lat`| Сборка секций WASM-модуля.                                     |
| `src/90_driver.lat`| Точка входа: полный проход компиляции.                         |

`shc.lat` генерируется — редактировать нужно части, затем пересобрать:

```sh
node selfhost/build.mjs        # src/*.lat -> shc.lat
```

## ABI компилятора

| Адрес   | Назначение                                                     |
|---------|----------------------------------------------------------------|
| 3145728 | входной исходник: `[len u32 LE][utf8 bytes]` (128K-область)     |
| 65536   | выходной WASM: `[len u32 LE][bytes]` после вызова `main()`      |

`main()` компилятора возвращает длину выходного WASM — либо **отрицательную**
величину при ошибке компиляции: тогда по адресу 65536+4 лежит `len` байт
UTF-8 текста ошибки (`[len u32 LE][utf8]`), который хост читает как сообщение.

> Входной исходник вынесен в отдельную высокую область, а не прижат к 32768:
> по мере роста `shc.lat` (>32K) его хвост перекрывал `OUTB`, который `binit()`
> зануляет на старте, — это молча портило последние токены (например, `FNLEN`
> превращался в `F`). Хост обязан нарастить память до адреса `INPUT_ADDR` перед
> записью исходника (`memory.grow`), так как компилятор растит её лишь в `main()`.

## Запуск

```sh
cargo build --bin latentc
node selfhost/bootstrap.mjs
```

`bootstrap.mjs` выполняет цепочку:

1. `latentc` (Rust) собирает `selfhost/shc.lat` → `stage1.wasm`;
2. `stage1.wasm` компилирует `selfhost/shc.lat` → `stage2.wasm` (self-compiled);
3. `stage2.wasm` компилирует `selfhost/shc.lat` → `stage3.wasm`;
4. проверяется `stage2 == stage3` (фиксированная точка).

## Тесты

```sh
node --test "selfhost/test/*.test.mjs"
```

* `bootstrap.test.mjs` — валидность stage1/2/3 и фиксированная точка.
* `lexer.test.mjs` — атомарные проверки `tokenize` по категориям токенов.
* `scoping.test.mjs` — область видимости локальных (`find_local`).
* `features.test.mjs` — дифференциальные тесты oracle(Rust) vs stage1 vs stage2.
* `build.test.mjs` — детерминизм и идемпотентность сборщика частей.

## Побочный результат: примитивы памяти

Для селф-хостинга в Rust-реализацию (`latentc`) добавлены встроенные
небезопасные примитивы линейной памяти: `alloc(size)`, `load8(addr)`,
`store8(addr,v)`, `load32(addr)`, `store32(addr,v)`, `memcopy(dst,src,len)`.
См. `src/codegen/emit_call.rs` (`compile_memory_builtin`).

> Примечание. Строковые литералы хранятся как `[len u32][utf8]`; оператор `+`
> над строками — конкатенация (не арифметика), поэтому байты литерала читаются
> по смещению `+4` после `memcopy`, а не через `s + 4`.
